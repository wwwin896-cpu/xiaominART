```bash

npm run dev
```

### 后台测试账号

- 用户名：由 `ADMIN_USER` 环境变量提供；本轮浏览器复验使用 `admin`
- 密码：由 `ADMIN_PASSWORD` 环境变量提供；本轮浏览器复验使用一次性隔离密码
- 登录页不预填密码；密码不写入源码、前端或交付包

本轮测试凭据只用于隔离复验，不能用于生产。

## 2. 支付边界

本次使用**内部模拟支付**，不是第三方沙盒。

- 模拟成功：创建“模拟支付成功”测试订单，并按测试规则扣减演示库存；
- 模拟失败：创建“模拟支付失败”记录，不显示为支付成功；
- 模拟取消：创建“已取消”记录，不显示为支付成功；
- 不收集银行卡信息；
- 不产生真实扣款；
- 没有真实支付网关、真实回调、真实收入或支付合规验证。

因此，**模拟支付成功不能表述为真实支付已验证**。

## 3. 标准商品下单操作证据

### 操作步骤

1. 打开首页，点击“挑一幅字”；
2. 进入 `/shop`，选择商品“福 · 把喜气写进日子”；
3. 进入 `/shop/fu`，确认页面显示“演示数据”“演示价”“斗方（演示）”；
4. 点击“加入购物车”；
5. 进入购物车 `/cart`；
6. 进入测试结算 `/checkout`；
7. 填写虚拟客户、虚拟联系方式和“测试地址，不用于真实配送”；
8. 选择“模拟成功”；
9. 勾选测试声明并创建订单；
10. 进入受保护的订单结果页，核对订单编号、状态、演示金额和商品快照；
11. 登录后台，核对测试订单记录和演示库存变化。

### 已验证结果

- 首页、商城、商品详情、结算和后台登录页面返回 HTTP 200；
- 服务端忽略客户端传入的伪造价格，订单金额按服务端商品数据核算；
- 本轮整改复验订单：`TEST-20260913-286FDE`，状态“模拟支付成功”，演示金额 `¥598`；
- 后台同单核对属于本轮用户 Chrome 隔离证据；历史订单编号不与本轮复验混用；
- 成功订单状态为“模拟支付成功”，不是现实付款；
- 订单写入 SQLite，刷新和重新查询后仍可读取；
- 订单项保存下单时商品名、规格、价格和工艺类型快照；
- 独件商品并发成功请求结果为一笔 201、一笔 409，未成功出售两次。

## 4. 定制需求提交操作证据

### 操作步骤

1. 打开 `/custom`；
2. 填写虚拟姓名和虚拟联系方式；
3. 选择“给家人”或其他演示场景；
4. 在“想写的文字”中填写 `平安喜乐` 或 `福`；
5. **不填写“你的故事”**；
6. 保持公开授权未勾选；
7. 提交测试需求；
8. 页面显示 `CUSTOM-...` 需求编号；
9. 登录后台查看同一条定制需求，状态为“新提交”。

### 已验证结果

- 不填写故事也能提交；
- 最新实测需求：`CUSTOM-20260913-88F8E9`，状态“新提交”；
- 后台已读取同一需求编号和状态：`CUSTOM-20260913-88F8E9 / 新提交`；
- 需求生成唯一编号；
- 需求写入 SQLite；
- 默认状态为“新提交”；
- 故事默认私密，不自动公开；
- 后台可读取需求编号、场景、文字、联系方式和状态。

对应截图：[定制提交成功](screenshots/04-custom-success.png)。

## 5. 后台查询对应记录操作证据

1. 打开 `/admin/login`；
2. 输入测试账号；
3. 登录 `/admin`；
4. 查看商品数量、测试订单、定制需求和投稿摘要；
5. 查看最近测试订单的订单编号、状态和演示金额；
6. 查看定制需求编号、状态、虚拟客户和提交时间；
7. 查看演示商品库存。

已验证：未登录访问后台 API 返回 401；登录后可读取商品、订单、定制需求和投稿摘要。对应截图：[后台](screenshots/05-admin.png)。
