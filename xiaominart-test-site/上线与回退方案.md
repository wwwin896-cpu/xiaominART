# xiaominART 上线与回退方案

> 当前状态：仅提供方案，所有正式上线动作均需用户明确批准
> 当前版本：待验收测试版

## 1. 正式上线前的前置门槛

只有以下项目全部完成并获得明确批准，才可进入上线执行：

1. 真实 SKU、价格、库存、规格和素材替换完成；
2. 商品和素材授权表完成；
3. 经营配置确认单完成；
4. 正式隐私、销售、配送和售后政策审阅完成；
5. 生产数据库、备份、HTTPS、密钥、限流、CSRF 和日志完成；
6. 真实支付沙盒验证完成，且不再使用测试模拟支付；
7. 生产环境预发布验收通过；
8. 用户明确批准域名切换和正式发布窗口。

## 2. 演示数据清理

### 测试环境保留

- 冻结版本保留 `F/L/S/X/C` 演示商品；
- 演示数据库只用于验收，不导入真实客户资料；
- 截图和测试报告保留，作为版本证据；
- 测试订单明确标记为测试状态，不计入真实营收。

### 生产切换前清理

1. 备份当前测试数据库和测试报告；
2. 创建新的生产数据库，不直接把测试数据库当生产库；
3. 导入经过批准的真实商品、价格、库存和政策；
4. 确认生产库没有虚拟客户、虚拟地址和模拟订单；
5. 运行数据审计：演示、待替换、待确认字段数量必须为 0，或由用户书面批准保留；
6. 关闭模拟支付入口和测试后台默认密码；
7. 重新验收生产环境。

禁止直接删除唯一数据源。清理前必须备份，并由用户批准数据保留期限。

## 3. 真实支付验证

1. 用户明确指定支付服务商和经营主体；
2. 技术负责人使用平台支持的安全授权机制配置沙盒，不在对话中粘贴密钥；
3. 使用沙盒测试账号完成成功、失败、取消、重复回调、退款/撤销（若适用）；
4. 核对支付状态、订单状态、库存变化和后台记录；
5. 验证生产密钥与沙盒密钥不会混用；
6. 保存支付验证记录和回调日志；
7. 用户明确批准后，才允许配置生产支付；
8. 生产支付上线后先进行低风险内部测试，不把测试订单当真实销售证明。

当前测试版没有第三方沙盒支付，只有内部模拟支付。

## 4. 备份方案

### 上线前

- 备份源码压缩包、依赖锁定文件、配置样例、数据库 schema、迁移说明和资产清单；
- 对生产数据库做完整备份并记录哈希/时间；
- 单独保存 DNS 旧记录、环境变量清单和回滚版本号；
- 验证备份可读取，不以“文件存在”代替恢复演练。

### 上线后

- 按经营者批准的周期执行数据库备份；
- 保留至少一个可回退代码版本；
- 记录发布版本、数据库变更和配置变更；
- 定期演练恢复到隔离环境；
- 备份不得包含公开可访问的管理员密钥或真实客户明文数据。

## 5. 域名切换方案

正式动作前必须由用户明确批准：

1. 确认生产站点健康检查通过；
2. 确认 `xiaominART.com` 的 DNS 当前记录并保存旧值；
3. 降低 TTL（如需要，提前完成并等待生效）；
4. 备份正式域名的 DNS 配置；
5. 在批准窗口内新增/修改目标记录；
6. 验证 HTTPS、首页、商品、结算、后台和 noindex/索引策略；
7. 逐地区检查解析和缓存；
8. 记录切换时间和验证结果。

本次冻结阶段不执行以上任何 DNS 操作。

## 6. 故障回退方案

### 触发条件

- 支付状态异常或重复扣款风险；
- 订单、库存或定制需求数据丢失；
- 未授权访问后台或泄露客户信息；
- 关键页面 5xx、资源大量 404 或严重支付错误；
- 正式商品、价格或政策出现重大错误。

### 回退步骤

1. 立即停止新订单/关闭生产支付入口；
2. 保留错误日志、订单记录和当前版本信息；
3. 不删除原生产数据；
4. 切回上一个已验收代码版本；
5. 如涉及数据库变更，使用经过验证的备份恢复到隔离环境，先核对后再替换；
6. 如涉及域名，恢复切换前保存的 DNS 记录；
7. 验证前台、后台、支付关闭状态、订单和库存；
8. 通知经营者并记录事故时间线；
9. 修复后重新测试，未经用户批准不再次上线。

### 目前冻结版的回退

- 停止 `npm run dev` 进程即可停止本地测试站；
- 不需要修改正式域名；
- 删除测试数据库前先备份；
- 重新启动会按 schema 自动创建演示数据库；
- 测试截图、验收报告和工程压缩包不随数据库清理删除。
