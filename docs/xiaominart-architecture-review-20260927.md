# XIAOMINART 网站架构调整方案评审意见

日期：2026-09-27

## 一、结论先行

这份方案的核心判断是正确的：网站不能继续用一套内容同时承担品牌展示、B 端项目咨询和 C 端快速选购，应该建立“品牌展厅”和“商品货架”两种呈现逻辑。

但我不建议按文档原样直接开发。方案需要从“完全拆成 Web 端和移动端两套产品”调整为：

1. 共享一套内容与商品数据；
2. Web 端与移动端采用不同的导航、信息密度和转化组件；
3. 第一阶段仍以现有网站作为品牌与决策中心；
4. 真实下单、购物车、订单和库存只在微信小程序或明确的交易系统准备完成后启用；
5. “雅礼”继续作为书法小品、器物手作和非遗面塑的统一品牌入口；
6. 企业礼赠、插画艺术邀约、非遗活动、展馆微缩沙盘归入 B 端企业定制体系，不与 C 端商品分类混在一起。

换句话说：方向采纳，结构需要收敛，实施需要分阶段。

## 二、方案中最值得采纳的部分

### 1. Web 端和移动端应该服务不同任务

文档将 Web 端定义为“品牌展示 + B 端市场服务”，将移动端定义为“商品浏览 + C 端消费体验”，这一判断符合当前业务闭环：

```text
小红书种草
→ 网站建立信任、帮助决策
→ 微信小程序完成商品成交
```

Web 端适合承载：

- 品牌定位
- 艺术家与工艺介绍
- 企业定制能力
- 案例与项目流程
- Journal 和 SEO 内容
- 复杂咨询表单

移动端或小程序适合承载：

- 快速浏览
- 品类筛选
- 现售款商品详情
- 收藏与心愿单
- 小程序下单
- 订单、支付、售后

### 2. 书法小品需要作品集和商品货架两种视角

同一件书法小品，在 Web 端可以被当作作品集内容展示，在移动端可以被当作礼品或空间装饰商品展示。这种差异是合理的，但不能复制两份数据。

建议同一条内容至少具备以下字段：

- 作品名称
- 品类：书法小品 / 器物手作 / 非遗面塑
- 销售模式：现售款 / 定制款
- 适用场合
- 适用对象
- 适用空间
- 书体或风格
- 尺寸
- 材质
- 装裱或包装信息
- 价格显示方式
- 小程序商品链接
- 商品状态
- 是否允许公开展示
- SEO 标题与描述

Web 和移动端只改变展示方式，不改变内容源。

### 3. 企业定制应该独立成为 B 端服务总入口

文档提出企业礼赠、插画艺术邀约、非遗面塑活动、展馆微缩沙盘四大服务方向，这比当前只突出企业礼赠更加完整。

建议建立一个“企业定制”总页，四个服务方向作为页内服务卡和独立锚点：

- 企业礼赠
- 插画艺术邀约
- 非遗面塑活动
- 展馆微缩沙盘

这四类服务的购买逻辑、报价方式、交付周期和咨询资料都不同，不宜直接放进普通 C 端商品列表。

### 4. 移动端底部导航适合小程序，但不应立即照搬到官网 H5

底部 Tab、拇指热区、固定操作栏等设计适合移动端，但需要区分：

- 官网移动端：负责内容浏览、选礼和咨询；
- 微信小程序：负责真实商品、购物车、支付、订单和售后。

当前项目还没有确认真实小程序商品链接、库存、订单和支付系统，因此官网移动端不能先做出“加入购物车 / 立即下单”的假交易体验。

## 三、需要调整的关键问题

### 1. “Web 端六个一级入口”与已确认的“雅礼”定位冲突

文档建议一级导航为：

- 首页
- 书法小品
- 非遗面塑
- 手作器物
- 企业定制
- 关于

这套导航对一个已具备大量商品内容的成熟电商站是清楚的，但当前 xiaominART 已明确形成“雅礼”的统一品牌概念：

- 书法小品
- 器物手作
- 非遗面塑

都属于雅礼的一部分。

如果把三类品类拆成三个一级入口，会削弱“雅礼”的品牌统摄能力，也会让顶部导航变长，移动端尤其明显。

### 建议的 Web 一级导航

```text
首页
雅礼
选礼指南
企业定制
品牌故事
```

其中：

```text
雅礼
├── 全部雅礼
├── 书法小品
│   ├── 现售款
│   └── 定制款
├── 器物手作
└── 非遗面塑
```

“书法小品”的 24 节气、中国传统节日和六类定制场合，应该作为页面内分类、筛选和 SEO 落地页，不要全部塞入顶部导航。

### 2. “企业定制”和“企业礼赠”需要统一命名

文档在不同段落使用了“企业定制”“企业礼赠”“商务伴手礼”。建议统一：

- 一级导航：企业定制
- 核心服务：企业礼赠
- 其他服务：插画艺术邀约、非遗面塑活动、展馆微缩沙盘

“企业伴手礼”不建议继续作为主命名，因为它会把企业业务缩小成单一礼品场景。

### 3. “插画艺术邀约”需要确认是否是独立真实业务

方案将插画艺术邀约列为核心业务，但当前品牌资料和现有内容模型主要围绕：

- 书写
- 礼品
- 器物
- 非遗内容
- 空间与企业定制

如果插画艺术邀约确实是已确认业务，应新增：

- 艺术家或插画师资料
- 可承接项目类型
- 商用授权边界
- 尺寸与媒介
- 案例或方向示例
- 询价字段

在上述资料未确认前，建议先使用“艺术邀约”作为预留服务类型，不能公开承诺已有完整插画团队或成熟案例。

### 4. “合作伙伴 Logo 墙、客户案例、活动效果数据”不能先做占位

方案建议首页加入：

- 合作伙伴 Logo 墙
- 2–3 个客户案例
- 面塑活动效果数据
- 客户评价

这些模块只有在获得真实授权和可核验数据后才适合公开。当前正确做法是：

- 有授权的真实案例：公开展示；
- 只有项目方向：标记为“方向示例”；
- 没有资料：暂不展示，不使用“合作伙伴即将呈现”等空白占位；
- 没有数据：不要制作活动效果数字。

### 5. “现售款”和“加入购物车”存在交易基础设施前置条件

方案将书法小品 Web 端和移动端都设计为可购买商品，并提出：

- 加入购物车
- 结缘价
- 下单
- 订单管理

但当前项目已经明确：

- 没有站内支付；
- 没有站内订单；
- 没有站内库存；
- 没有确认的真实小程序商品链接；
- 当前表单主要是邮件草稿或本地交互，不是稳定后台接收。

因此分两阶段：

#### 当前阶段

现售款可以展示：

- 作品图片
- 作品名称
- 参考价格或结缘价
- 可售状态
- 包装信息
- 小程序配置状态
- “获取结缘信息”或“进入小程序”入口

未配置真实商品链接时，必须继续显示咨询入口，不能显示虚假下单按钮。

#### 交易准备完成后

只有完成以下配置后，才启用直接购买：

- 真实小程序商品 ID
- 商品链接
- 库存来源
- 价格确认
- 配送规则
- 售后规则
- 订单和支付链路
- 购买数据埋点

### 6. 移动端四 Tab 缺少首页和搜索/选礼入口

文档建议移动端 Tab 为：

- 书法小品
- 非遗面塑
- 手作器物
- 故事

这个结构对于品类浏览是直观的，但会产生两个问题：

1. 用户没有明确的首页入口；
2. 想按预算、场合或对象选礼的用户没有一级入口。

如果移动端是小程序，建议优先考虑：

```text
首页
雅礼
选礼
故事
```

其中“雅礼”页内再提供：

- 书法小品
- 器物手作
- 非遗面塑

如果产品数据和交易量发展到足够规模，再测试把“雅礼”拆成品类 Tab。

## 五、内容模型建议

### 1. 书法小品

建议在 Keystatic 中使用一个产品集合，通过字段区分现售和定制：

```text
productType: calligraphy
saleMode: ready-made | custom
availability: draft | published | inquiry-only | available | unavailable
occasionType: seasonal | festival | personal
seasonalTerm: 24 节气中的一个值
festival: 中国传统节日中的一个值
customOccasion: birthday | housewarming | opening | festival | teacher-thanks | anniversary
priceMode: fixed | range | inquiry
miniProgramStatus: unconfigured | ready | unavailable
```

不要把“现售款”和“定制款”维护成两套完全不同的产品结构，否则后续详情页、图片、SEO 和统计会重复建设。

### 2. 器物手作

建议字段包括：

- 器物类型
- 材质
- 尺寸
- 使用场景
- 工艺说明
- 现售或定制状态
- 包装信息
- 价格模式
- 小程序链接状态

### 3. 非遗面塑

建议拆分为三种内容关系，而不是只做一张作品卡：

- 面塑作品
- 面塑人物 / IP
- 面塑活动 / 企业服务

这样既能支持移动端种草，也能支持企业定制页面。

### 4. 企业定制服务

服务集合至少需要：

- 服务名称
- 服务类型
- 适用客户
- 适用场景
- 最小资料要求
- 典型交付物
- 参考周期
- 预算是否公开
- 案例授权状态
- 咨询表单类型
- SEO 字段

## 六、实施优先级建议

### P0：先统一架构和内容边界

1. 确认一级导航使用“雅礼”还是直接拆三类品类；
2. 建立书法小品 `现售款 / 定制款` 字段；
3. 建立节气、传统节日和六类定制场合词表；
4. 把企业礼赠、插画邀约、面塑活动、展馆沙盘归入企业定制服务；
5. 暂不启用虚假购物车、订单和支付；
6. 明确哪些作品是现售、哪些是定制、哪些只是方向示例。

### P1：完成 Web 端内容和页面

1. 雅礼总览页；
2. 书法小品作品集页；
3. 书法小品现售款页；
4. 书法小品定制款页；
5. 器物手作页；
6. 非遗面塑页；
7. 企业定制总页；
8. 四个企业服务方向页内锚点；
9. 作品详情页统一模板；
10. SEO 与面包屑结构。

### P2：建设移动端 / 小程序体验

1. 移动端底部导航；
2. 雅礼品类页；
3. 按送礼与按空间用途的筛选；
4. 现售款详情页；
5. 收藏与心愿单；
6. 真实小程序商品链接；
7. 购买、订单、支付、配送和售后链路。

### P3：数据与增长

1. 按品类统计浏览；
2. 按节气、节日和场合统计点击；
3. 统计咨询开始与提交；
4. 统计小程序跳转；
5. 统计现售款转化；
6. 区分 Web B 端线索和移动端 C 端成交。

## 七、我建议暂缓的事项

以下事项在资料和系统准备完成前不应直接开发成公开承诺：

- 合作伙伴 Logo 墙
- 未授权客户评价
- 活动效果数据
- 统一购物车
- 站内订单中心
- 站内支付
- 真实库存显示
- 24 小时联系承诺
- 固定交付周期承诺
- “销量第一”“服务过多少客户”等数字背书

## 八、最终意见

这份方案适合作为“第二阶段产品架构蓝图”，不适合作为一次性重做清单。

我建议采纳以下核心方向：

- Web 端做品牌展厅和 B 端服务；
- 移动端 / 小程序做商品货架和 C 端成交；
- 同一套 Keystatic 内容，分别呈现；
- 书法小品区分现售款和定制款；
- 器物手作与非遗面塑纳入雅礼体系；
- 企业礼赠、插画邀约、面塑活动、展馆沙盘纳入企业定制体系。

我不建议原样采用以下内容：

- 直接把书法、面塑、器物拆成三个一级导航；
- 在真实交易系统未接入前做购物车和订单承诺；
- 使用未经授权的客户案例、Logo、评价和效果数据；
- 立即建设两套完全独立、重复维护的 Web 与移动端内容系统；
- 用“企业伴手礼”代替更完整的“企业定制”业务入口。

最稳妥的下一步是先完成“雅礼内容模型 + Web 端品类页面 + 企业定制总页”，再根据真实商品链接和小程序能力建设移动端交易体验。
