# 小民艺术 · 作品编码与防伪查询方案 v2.1

> 制定日期：2026-10-14
> 回答的问题：**客户能否通过编码查到「哪一年的作品」「是否正宗原版」**
> 诚实前提：**单靠编码无法防伪**，必须靠「编码 + 官网公开档案 + 实物证书」三层结构

---

## 一、先说结论（避免误解）

| 客户想知道 | 编码能做到吗 | 靠什么实现 |
|---|---|---|
| **这是哪一年的作品？** | ✅ **能，直接读出** | 编码第 ④ 段「年份码」 |
| **这是不是正宗原版？** | ⚠️ **编码只能做到一部分** | 需要配合「官网公开档案页」+「实物证书」 |

**必须讲清楚的一点**：任何印在作品上的编码，理论上都可以被人抄走、伪造。
**编码的作用不是「防止被伪造」，而是「让伪造更容易被发现」。** 真正的防伪靠组合拳。

---

## 二、编码结构（七段式 v2.1）

```
XMA - CL - WA - 26 - 0001 - T2 - 0
 ①    ②    ③    ④    ⑤     ⑥    ⑦
```

| 段 | 名称 | 位数 | 取值 | 作用 |
|---|---|---|---|---|
| ① | 品牌前缀 | 3 | `XMA` 固定 | 标明出品方 |
| ② | 品类码 | 2 | 见码表 | 书法/手作/器物/企业/合作 |
| ③ | 形态码 | 2 | 见码表 | 摆件/圆光/挂墙/扇面… |
| ④ | **年份码** | **2** | 如 `26` | **★ 回答「哪一年的作品」** |
| ⑤ | 流水号 | 4 | `0001`–`9999` | 该「品类-形态-年份」内序号 |
| ⑥ | 档位码 | 2 | `T1`–`T5` | 价格档，可单独变更 |
| ⑦ | 校验位 | 1 | `0`–`9` | **防抄错**（详见第四章） |

### 年份码的规则

**年份码 = 作品完成年份，不是上架年份。**

例：
- 2025 年写好的作品，2026 年才上架 → 年份码仍是 `25`
- 2026 年写好的作品 → 年份码 `26`

**这才是客户问「几几年的作品」时想要的答案。**

### 流水号的分段方式（v2.1 变更）

**按「品类-形态-年份」独立编号**：

| 范围 | 含义 |
|---|---|
| `CL-SG-26-0001` ~ `CL-SG-26-9999` | 2026 年的书法摆件 |
| `CL-SG-27-0001` ~ | 2027 年的书法摆件（年份变了，从头开始） |
| `CL-WA-26-0001` ~ | 2026 年的书法挂墙 |

好处：客户看到 `CL-SG-26-0005`，立刻知道是「2026 年第 5 号摆件」。

## 四、校验位：它的真实作用与局限

### 算法（位置加权模 10）

```
1. 取主体（前六段，去掉校验位）：XMA-CL-WA-26-0001-T2
2. 去掉连字符，字母转数字（A=1, B=2, ... Z=26）
   → 241301 312 231 26 0001 202
   → 241301312231260001202
3. 按位置加权求和，权重序列 (1,3,7,9,5,11,13) 循环
4. 校验位 = (10 - (总和 mod 10)) mod 10
```

**可运行实现**：见 `outputs/code_tool.py`（`calc_check()` / `make_code()` / `verify_code()`）

### 它能做什么 ✅

**检出抄写错误**。例如客户手抄时把 `0001` 误写成 `0002`，或把 `T2` 写成 `T3`——校验位立刻不匹配。

实测（见 `code_tool.py` 运行输出）：
- 改序号：✅ 检出
- 改档位：✅ 检出
- 改年份：✅ 检出
- 改品牌前缀：✅ 检出

### 它不能做什么 ❌

**挡不住刻意伪造。** 1 位校验位只有 10 种可能，命中率 10%。

实测中确有一条构造出来的编码通过了校验（`XMA-CL-SG-26-0007-T1-6` 在 v2.0 算法下误判为真）。

> **这正是必须在方案里加官网公开档案的原因。** 校验位不是防伪，是防错。

## 五、三层防伪体系（这才是完整答案）

### 第一层 · 编码本身（弱）

**作用**：年份可读 + 抄写错误可检出
**成本**：0（编码规则本身）
**防住什么**：客户抄错、销售报错编号

### 第二层 · 官网公开作品档案（核心）★

**作用**：让每一幅作品在互联网上有一份公开存证
**成本**：低（一个页面模板）

**方案**：为每幅作品生成公开档案页

```
https://xiaominart.com/verify/XMA-CL-WA-26-0001-T2-0
```

**页面内容**：

```
┌────────────────────────────────────────────┐
│  xiaominART  作品档案                       │
│                                            │
│  ┌──────────────┐  编码：XMA-CL-WA-26-0001-T2-0
│  │              │  品名：清欢
│  │  作品高清图  │  创作年份：2026 年
│  │              │  材质：赭底宣纸 · 榫卯柚木框
│  │              │  尺寸：60 × 33 cm
│  └──────────────┘  编号：2026 年第 1 号挂墙作品
│                                            │
│  释读：「人间有味是清欢」，苏轼写给寻常日子的七个字。
│                                            │
│  状态：● 在售                                │
│  ──────────────────────────────────────    │
│  此页为该作品的唯一公开档案。如你手中的作品     │
│  编码与此页一致但图像不符，请联系我们核实。     │
└────────────────────────────────────────────┘
```

**为什么这是防伪主力**：

| 仿冒者要做的 | 难度 |
|---|---|
| 抄到正确编码 | 容易 |
| 伪造一幅**视觉完全一致**的作品 | **极难** |
| 让客户相信「编码对得上」 | 需要客户**不去查官网** |

**只要官网档案页存在且可搜索，仿冒者就无法过关。**

**额外收益**：这个页面能被搜索引擎收录 → 客户搜编码 `XMA-CL-WA-26-0001-T2-0` 就能找到官网 → **顺手完成 SEO 获客**。

### 第三层 · 实物证书 + 手写签名 + 印鉴（物理唯一性）

**作用**：证明实物的唯一性
**成本**：你现有证书体系已具备，只需加编码

**证书排版建议**：

```
    ┌──────────────────────────────────┐
    │         xiaominART               │
    │                                  │
    │         作 品 编 号               │
    │    XMA-CL-WA-26-0001-T2-0        │
    │                                  │
    │    品名：清欢                     │
    │    创作年份：2026 年              │
    │    材质：赭底宣纸 · 榫卯柚木框     │
    │    尺寸：60 × 33 cm               │
    │                                  │
    │                                  │
    │           升斗小民   [朱红印鉴]    │
    │            （手写签名）            │
    └──────────────────────────────────┘
```

**仿冒者要同时伪造**：证书纸张 + 印鉴 + 手写签名 + 装裱工艺 + 作品本身。**五重门槛，成本极高。**

## 七、客户查询流程（完整交互）

### 场景 A：客户在官网输入编码

```
┌──────────────────────────────────────┐
│   查询你的作品档案                     │
│   ┌────────────────────────────┐     │
│   │ XMA-CL-WA-26-0001-T2-0     │     │
│   └────────────────────────────┘     │
│            [ 查 询 ]                  │
│                                      │
│   ✅ 编码格式有效                     │
│   → 跳转作品档案页                    │
└──────────────────────────────────────┘
```

**若编码不存在于系统** → 显示「该编码未登记 / 请联系我们核实」，**这才是真正的验真关卡**（因为档案库里只有真编码）。

> ⚠️ 关键设计：**校验位通过 ≠ 作品为真**。真正的判定是「该编码是否在官网档案库中存在」。所以这个查询必须有**后台数据支撑**，不能只做前端计算。

### 场景 B：客户直接访问档案页

`xiaominart.com/verify/{编码}` → 显示档案（如上图）。

### 场景 C：客户没编码，只有实物

引导客户找证书上的编码 → 或联系客服人工核对。

## 八、技术实现清单（供开发参考）

| 模块 | 内容 | 优先级 |
|---|---|---|

## 九、老作品怎么办（编码迁移规则）

你之前可能已经有作品给过客户，处理规则：

| 情况 | 处理 |
|---|---|
| 已售出、客户手上有作品，但没编码 | **不追发新编码**（会与证书不符）。可在档案页补录，编码用「补录专用段」`XMA-CL-XX-{年份}-{序号}-T?-?` 标记为历史作品 |
| 已售出、有旧版编码 | **保留旧编码**，不做迁移。新旧编码在档案页做映射 |
| 未售出、尚未印证书 | **直接启用新编码** |

**核心原则：已经到客户手上的东西，编码永不追改。**

## 十、二维码扫码验真（2026-10-14 已上线）

### 为什么加二维码

编码是 22 个字符。**没有人愿意手输 22 个字符去查真伪。**
二维码把这一步降到「举手机扫一下」——这是手机上唯一现实可行的方式。

### 两种码，用途完全不同（别混）

| | A 类 · 证书档案码 | B 类 · 官网分享码 |
|---|---|---|
| 印在哪 | 实物藏品证书上 | 网页 / 宣传物料 |
| 扫出来的内容 | 该作品档案页 URL（带校验位完整编码） | 可能是另一件作品的演示 |
| 能否溯源 | **可以**——码与作品一一绑定 | 不能，仅作演示 |
| 本项目状态 | **已随每件作品的档案页内置** | 未做 |

> ⚠️ **二维码本身可以被复制。** 仿冒者扫一遍就能把码抄到自己的假货上。
> 所以二维码**不是防伪手段，只是便利入口**。
> 真正的验真关卡仍然是那道老问题：**那幅笔迹他拿不到。**

### 扫码后的三段式漏斗（已实现）

顺序是刻意设计的——**先给结论建立信任，再索取关注，最后才谈转化**：

```
客户举手机扫证书上的码
   ↓
① 验真段（档案页面上方，即时给出权威结论）
   「在册原件 · 2026 年创作 · 第 1 号挂墙作品」
   + 真品实拍图  ← 关键：用于笔迹比对
   ↓
② 二维码区块（文案引导：手机一扫直达，无需手输）
   + 「码可复制，笔迹不可复制」的诚实说明
   ↓
③ 转化段
   第 ② 步 关注 —— 「想看到这幅字的创作过程？」
                   长按识别公众号二维码 / 添加微信
   第 ③ 步 定制 —— 「也想有一件属于你的？」
                   进入定制咨询（带来源编码归属）
```

### 三个必须知道的技术边界

1. **二维码能复制** → 它是入口不是防线，防线是档案页上的实拍图
2. **微信内网页无法一键跳转关注公众号** → 只能用「长按识别二维码」引导，
   这是微信的硬限制，任何方案都绕不过
3. **扫码留痕需要后端** → 扫码动作发生在微信/相机里，网站无从得知。
   现在只能记录「档案页被打开」（事件 `archive_view`），近似等于扫码量

### 公众号未就绪时的降级（已实现）

`src/data/site.ts` 里的 `mpName` / `mpQr` **留空时，关注段整段自动隐藏**，
自动降级为只展示个人微信——不会出现空二维码或死链。
业主拿到公众号后，把图片放进 `public/assets/images/` 再把路径填上即可，**无需改代码**。

### 质量保证

二维码由**纯前端零依赖**代码生成（`src/lib/qr.ts`），不调用任何外部二维码 API ——
避免把「客户扫了什么码」泄露给第三方，且静态生成时 SVG 直接写进 HTML，零运行时请求。

**「生成成功」不等于「扫得出来」** —— 格式位序或掩码错一处，图看着像二维码但任何手机都扫不出。
因此设有回归脚本 `scripts/check-qr.mjs`，用**独立解码器 jsQR** 回读比对：

```bash
NODE_OPTIONS="" node scripts/check-qr.mjs    # 期望 6/6 通过
```

实测结果：单元层 6/6、构建产物层 12/12、线上真实页面 ✅ 全部通过。

## 十一、10 条速查

1. 编码第 ④ 段 = **创作年份**，直接回答「哪一年的作品」
2. 年份 = 完成年份，**不是上架年份**
3. 校验位的作用是**防抄错**，不是防伪
4. **真正的防伪靠官网公开档案页**（仿冒者拿不到那幅画）
5. 编码查询必须**查后台库**，不能只做前端校验
6. 已到客户手上的编码，**永不追改**
7. 流水号按「品类-形态-年份」分段
8. 档位码可单独变更，主编码不动
9. 证书印**完整编码**（含校验位）+ 手写签名 + 印鉴
10. 档案页顺手做 SEO——客户搜编码就能找到官网
