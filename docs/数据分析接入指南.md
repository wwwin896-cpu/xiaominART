## 二、工具选型建议

| 工具 | 用途 | 优点 | 注意 |
|---|---|---|---|
| **百度统计**（✅ 2026-10-09 已接入） | 流量/来源/访客 | 国内访问稳定、不依赖境外网络、免费 | ID 固定写死在 `Layout.astro`（公开标识，非密钥） |
| **Umami**（推荐首选） | 流量/来源/转化漏斗 | 自托管或云托管皆可，隐私友好，脚本 <2KB，无 Cookie | 需要自己部署（自托管或云托管 + Postgres；**注意别再用 Vercel Hobby 承载——该档位禁止商业用途，本站正是为此迁到 Cloudflare**） |
| **GA4** | 渠道归因、与 Google Ads/Search Console 联动 | 免费生态全 | 脚本较重；广告拦截器拦截率高；国内访问不稳 |
| **Clarity** | 热图、会话回放、死点检测 | 微软出品免费，自动脱敏输入框 | 回放对性能有轻微影响，可按需开 |

> **统计闸门**：所有分析脚本统一受 `noindex` 约束（`Layout.astro` 的 `trackPage`）——
> 功能页与内部后台（`/wishlist/`、`/progress/`、`/admin/*`）不注入任何统计，
> 避免后台访问污染访客数与转化率口径。

## 三、⚠️ CSP 同步更新（必做，否则脚本被拦截）

`public/_headers` 的 CSP 已于 2026-10-07 转为**强制**。接入分析工具时必须扩白名单：

- **百度统计**（已加）：`script-src` 加 `https://hm.baidu.com`；`connect-src` 与 `img-src` 同时加 `https://hm.baidu.com https://*.baidu.com`（打点走 img/beacon，且备用域为 `*.baidu.com`）
- **GA4**：`script-src` 加 `https://www.googletagmanager.com`；`connect-src` 加 `https://*.google-analytics.com https://region1.google-analytics.com`
- **Umami**：`script-src` 加 Umami 域名（与 `PUBLIC_UMAMI_SRC` 同域）；`connect-src` 同样加该域
- **Clarity**：`script-src` 加 `https://www.clarity.ms`；`connect-src` 加 `https://*.clarity.ms`

改完 `_headers` 后按惯例 `curl -D -` 逐项核对响应头（历史上同段覆盖踩过坑）。

## 四、GA4 转发站内事件（可选）

站内事件已统一走 `xiaominart:event` CustomEvent → `/api/event`。若想让 GA4 也收到同名事件，在 `cloud-forms.ts` 的 `trackEvent()` 成功分支里加一行：

```ts
declare global { interface Window { gtag?: (...args: unknown[]) => void } }
window.gtag?.('event', name, data);
```

## 五、UTM 规范

所有外投链接（小红书、公众号、朋友圈、异业合作）统一：

```
https://xiaominart.com/?utm_source={渠道}&utm_medium={形式}&utm_campaign={活动}&utm_content={素材}
```

| 参数 | 约定值 | 示例 |
|---|---|---|
| `utm_source` | 小写平台名 | `xiaohongshu` / `weixin` / `zhihu` |
| `utm_medium` | `social` / `article` / `qr` / `dm`（私信） | `social` |
| `utm_campaign` | `y{年}{月}-{主题}` | `y2610-qixi` |
| `utm_content` | 素材标识 | `note-a` / `video-01` |

示例：小红书笔记挂店铺链接
`https://xiaominart.com/gifts/ready-made/?utm_source=xiaohongshu&utm_medium=social&utm_campaign=y2610-现货&utm_content=note-a`

### 5.1 渠道是怎么被记下来的（2026-11-02）

`src/scripts/attribution.ts` 在每次页面加载时解析 URL 与 referrer，归一成 6 个渠道，写进
`sessionStorage`（键 `xm-attribution`，**不设 Cookie**，会话内首触优先），随后由
`trackEvent()` 自动附在**每一条**事件上（字段 `ch` / `src` / `cmp` / `lp`）。
调用方不需要逐处传，也不会出现「某个新按钮忘了带来源」。

| `ch` 取值 | 命中条件 |
|---|---|
| `xiaohongshu` | `utm_source` 含 xhs / xiaohongshu / 小红书，或 referrer 来自 `xiaohongshu.com`、`xhslink.com` |
| `wechat` | `utm_source` 含 wechat / weixin / wx / 微信 / 公众号 / 朋友圈，或 referrer 来自微信域 |
| `offline` | `utm_medium=qr` 或 `utm_source` 含 offline / 线下 / 物料 / 展签 / 扫码 / 门店 |
| `search` | `utm_medium=organic` 或 `utm_source` 含 baidu / google / bing / sogou，或 referrer 是搜索引擎 |
| `referral` | 其他站外链接 |
| `direct` | 无 utm、无 referrer（直接输入网址、从 App 内打开、隐私浏览器） |

**注意**：微信内置浏览器常把 referrer 抹掉，所以微信渠道**必须带 utm**，否则会落进 `direct`。
小红书同理（站内打开链接多为无 referrer）。线下二维码必须带 `utm_medium=qr`。

### 5.2 线下物料的固定写法

```
https://xiaominart.com/?utm_source=offline&utm_medium=qr&utm_campaign={物料名}
```

`utm_campaign` 建议 `museum-a` / `hotel-b` / `exhibition-2026-spring` 这种可读短名，
一张物料一个名字；换一批物料就换名字，否则事后分不清是哪一批带来的。

## 六、怎么证明统计真的在工作（2026-11-02）

「代码里有」不等于「真的发出去了」。本站提供一条可复跑的验收命令：

```bash
npm run build && npm run verify:analytics        # 验本地 dist
npm run verify:analytics -- --url=https://xiaominart.com   # 验线上
```

它不读代码，只用真实 Chromium 走一遍，逐项断言：

1. **未同意时**：零个 `hm.baidu.com` 请求（PIPL 要求「同意后才加载」，不是「先加载再屏蔽」）
2. 点「同意并启用」后：`hm.js?<siteId>` 返回 **200 且 body > 10KB**
   （百度对不存在的 ID 也回 200 但 body 为空 —— 所以必须比字节数，光看状态码会被骗）
3. `hm.gif` 打点请求 200、`window._hmt` 已实例化
4. 四段漏斗真的上报：`gift_detail_view` / `wishlist_add` / `gift_advice_click` / `lead_submit_success`
5. 四条 UTM 链接分别被识别成 `xiaohongshu` / `wechat` / `offline` / `search`

手动核对（业主口径：Network 里看得见才算）：DevTools → Network → 过滤 `baidu`
→ 点「同意并启用」→ 应出现 `hm.js?ecd08d2b…`（约 29KB）与 `hm.gif?…&si=ecd08d2b…`。

> 页面源码里现在有 `<meta name="baidu-tongji-id" content="ecd08d2b…">`。
> 加这个 meta 的原因很实际：此前站点 ID 只以 JS 变量形式存在于内联脚本中，
> 搜源码搜不到，容易被误判为「没接统计」。ID 是公开标识，写出来不构成风险。

## 七、两套统计的分工（重要）

本站同时跑两套，不是重复建设：

| | 百度统计（第三方，需同意） | 自建 `/api/event`（第一方，不需同意） |
|---|---|---|
| 记什么 | 访客数、来源、停留、跳出、地域、设备 | 具体作品与按钮：看哪件、收藏哪件、点了哪个 CTA、表单成没成 |
| 依赖 | 用户点了「同意并启用」才加载 → **同意率决定数据量** | 不依赖同意，不设 Cookie，任何人访问都记 |
| 看在哪 | 百度统计后台（事件分析里筛 `funnel`） | WorkBuddy 云库 `site_events` 表 |

结论：**漏斗看第一方，流量与渠道看百度**。只盯百度后台会得出「没有数据」的错误结论 ——
在同意率不高的站点上，第三方统计天生只能看到一部分访客；而第一方事件从第一位访客就开始记。
