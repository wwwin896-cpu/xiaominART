## 一、后台能管理什么

站点有**两个后台**，用途不同：

**① 内容后台（Keystatic）** —— https://xiaominart.com/keystatic/
直接读写 GitHub 仓库里的内容文件，保存即提交，2~3 分钟后自动上线。

| 板块 | 能做什么 |
|---|---|
| 产品与礼品 | 新增/编辑礼品：名称、品类、价格区间、寓意、包装、发货说明、SEO、图文详情 |
| 选礼指南 / 场合 | 按场合的指南页（生日、乔迁、开业……）及推荐礼品关联 |
| 选礼指南 / 对象 | 按对象的指南页（送长辈、送老师……）及推荐礼品关联 |
| 渠道专题 | 小红书/微信承接页（默认不发布，做好再开） |
| 帮助中心 / FAQ | 常见问题增删改 |
| 客户故事 | 脱敏客户故事（默认不发布，**须先勾选「已获公开授权」**） |
| **现货上下架** | **十二幅现货的「已售出 / 在售」状态**（见「三·D」） |

**② 定制进度后台** —— https://xiaominart.com/admin/progress
录入/更新每个定制项目的进度，客户凭查询码自助查看。详见 **「三·B」**。

**两个后台都不能改的**（在代码里，找 AI 或开发者改）：
- 导航栏结构与栏目名称（`src/data/content.ts`）
- 页面版式、新增页面/板块
- 首页各区块的文案排布（大部分在代码里）
- 创作者介绍（`src/data/content.ts` 的 artists）

## 二、首次启用（只需做一次）

1. 在项目文件夹运行 `npm run dev`，打开 `http://localhost:4321/keystatic`
2. 点击 **Log in with GitHub** → 首次会进入「Create GitHub App」向导：
   - App 名字随意（如 `xiaominart-admin`）
   - 「Deployed project URL」填 `https://xiaominart.com`
   - 一路授权，GitHub App 安装到 `wwwin896-cpu/xiaominART` 仓库
3. 完成后项目根目录 `.env` 里会出现 4 个值：
   `KEYSTATIC_GITHUB_CLIENT_ID`、`KEYSTATIC_GITHUB_CLIENT_SECRET`、
   `KEYSTATIC_SECRET`、`PUBLIC_KEYSTATIC_GITHUB_APP_SLUG`
4. 把这 4 个值交给 AI（或自己在 Cloudflare Pages → xiaominart 项目 →
   Settings → Environment variables 配置），部署一次后线上后台即可登录
5. 若登录时 GitHub 提示 redirect_uri 问题：GitHub → Settings →
   Applications → Installed GitHub Apps → 找到该 App → Configure →
   Callback URL 确认包含 `https://xiaominart.com/api/keystatic/login`

**自动部署**：需在 GitHub 仓库 Settings → Secrets and variables → Actions
添加两个 secret，后台保存的内容才能自动上线：
- `CLOUDFLARE_API_TOKEN`（部署用的 Cloudflare 令牌）
- `CLOUDFLARE_ACCOUNT_ID` = `fc5bdc20f05edbbfa43081b6a8f6c672`

配置好后流程：后台保存 → 自动提交 GitHub → Action 自动构建 → 约 2-3 分钟上线。
（未配置 secret 期间，改动只进 GitHub，需要手动/AI 部署。）

## 三、日常怎么改内容

1. 打开 https://xiaominart.com/keystatic/ → Log in with GitHub（用有仓库写权限的账号）
2. 左侧选板块 → 新建或点开条目编辑
3. 改完点 **Save**（保存到 GitHub，默认分支 main）
4. 等 2-3 分钟自动上线；可用手机无痕窗口刷新确认
5. 改错了？GitHub 仓库提交历史可以回滚（Revert commit），或找 AI 处理

**写图文正文的技巧**：正文支持 Markdown——
`## 小标题`、`**加粗**`、`- 列表`、`[链接文字](/gifts/)`、图片 `![说明](/assets/xxx.jpg)`
（图片文件需先放进仓库 `public/assets/` 目录，可找 AI 上传，或在 GitHub 网页端 Add file 上传）。

## 三·B、定制进度后台（/admin/progress）

> 2026-10-07 新增。用于录入与更新**定制项目的进度**，客户凭专属查询码在 `/progress/` 自助查询。

### 怎么用

1. 打开 **https://xiaominart.com/admin/progress**
2. 首次会要求输入密钥 —— 就是 Cloudflare 里配的 `ADMIN_ACCESS_KEY`（见下方「三·C」）。
   输入正确后会存在**你自己这台浏览器**里，之后不用重复输入。
   （换设备/清缓存后需重新输入；密钥不会发到任何第三方。）
3. 「新建项目」填：项目名（如「张先生 · 乔迁横批」）、联系方式提示（如「尾号 8823」，
   **只写识别用的片段，不要写完整手机号**）、当前阶段、备注。
4. 保存后系统自动生成一个**查询码**，形如 `XM-7K2P9A`。点「复制」发给客户。
5. 项目推进时，回到这个页面把阶段改到下一步即可。

### 六个阶段（与客户看到的时间线一一对应）

| 阶段值 | 客户看到的 |
|---|---|
| `received` | 已收到愿望 |
| `review` | 字句审核 |
| `match` | 书体匹配 |
| `writing` | 创作中 |
| `delivery` | 待交付 |
| `done` | 已交付 |

> ⚠️ 查询码相当于客户项目的钥匙，**只在沟通时定向发给本人**，不要公开发布。
> 页面已在搜索引擎层面 `noindex`，但真正的保护来自「码不外传」。

### 客户侧入口

**https://xiaominart.com/progress** —— 输入查询码，看到自己的项目走到哪一步。
客户只能查到**属于自己那一个码**的内容，且看不到完整联系方式（只显示你填的「联系方式提示」）。

## 三·C、需要配置的密钥与环境变量

> **所有密钥都在同一个地方配**，不是在网站里点开关。
> 位置：**Cloudflare Pages → 项目 xiaominart → Settings → Environment variables**

快捷入口（复制到浏览器）：
`https://dash.cloudflare.com/?to=/:account/pages/view/xiaominart/settings/environment-variables`

打不开时的点击路径：登录 https://dash.cloudflare.com →
左侧 **Workers 和 Pages** → 点 **xiaominart** → 顶部 **Settings** → 左侧 **Environment variables**。

> ⚠️ **两个必须注意的坑**
> 1. 每个变量都要在 **Production** 和 **Preview** 两个环境各填一遍（或添加时选 "All environments"）。
>    只填 Production 的话，预览部署不生效。
> 2. **配完必须重新部署一次**：Cloudflare Pages → 项目 xiaominart → **Deployments** →
>    最新一次部署右侧 **⋯** → **Retry deployment**。环境变量不会自动生效。

| 变量名 | 填什么 | 激活什么 |
|---|---|---|
| `FORMS_ACCESS_KEY` | 云端访问密钥（向 AI 索取） | 站内表单真实提交 + `/progress` 查询 |
| `ADMIN_ACCESS_KEY` | **自己设一个强密码**（20 位以上随机串） | `/admin/progress` 录入后台 |
| `KEYSTATIC_GITHUB_CLIENT_ID` | 首次访问 /keystatic 时由向导生成 | Keystatic 内容后台登录 |
| `KEYSTATIC_GITHUB_CLIENT_SECRET` | 同上 | 同上 |
| `KEYSTATIC_SECRET` | 同上 | 同上 |
| `PUBLIC_KEYSTATIC_GITHUB_APP_SLUG` | 同上 | 同上 |

`ADMIN_ACCESS_KEY` 是**你自己定的**，不是别人给你的。建议用密码管理器生成随机串，
别用 `xiaomin2026` 这类好猜的。它只用于后台登录，请勿写进任何前端代码或公开场合。

### 怎么确认配好了

不用登录后台，直接在浏览器打开这两个地址看返回：

| 地址 | 配置前 | 配置成功后 |
|---|---|---|
| `https://xiaominart.com/api/progress?code=XM-AAAAAA` | `503 查询服务暂未配置完成` | `404 没有找到对应的项目` ✅ |
| `https://xiaominart.com/api/admin/progress` | `503 后台尚未配置密钥` | `401/403 密钥无效` ✅ |

> **503 变 404/401 就是成功了** —— 说明密钥已生效，只是测试数据不存在或没带密钥。
> 如果配置完仍是 503，说明变量名写错、或没重新部署；如果变成 `500`，请把返回内容发给 AI。

### 接入第三方分析（GA4 / Umami 等）

除了环境变量，还需**同步修改 CSP 白名单**（否则浏览器会拦截统计脚本）。
详见 `docs/数据分析接入指南.md`，规则写在 `public/_headers`，改完同样要重新部署。

## 三·D、现货作品的上架 / 售出 / 下架

> 2026-10-08 新增。现货十二幅**每幅世间唯一**，卖掉一幅就不能再当在售展示。
> 此前这个状态写死在代码里，需要找开发者改；现在您自己在后台勾一下即可。

### 卖出一幅时怎么做

1. 打开 **https://xiaominart.com/keystatic/** → 左侧 **现货上下架**
2. 找到对应那幅作品（列表里的一行 = 一幅作品，文件名就是作品标识，**请不要改文件名**）
3. 勾上 **「已售出」** → 保存
4. 顺手在 **「售出日期（内部备注）」** 填个日期，**「内部备注」** 写买家或交付方式（这两项只在后台可见，不会显示在网站上）
5. 等 2-3 分钟自动上线

勾上之后网站上会同时发生四件事：

| 位置 | 变化 |
|---|---|
| 现货列表页 | 卡片显示「已售出」角标、价格加删除线、图片降透明度，入口文案改为「看看这一幅」 |
| 作品详情页 | 顶部出现售出说明，购买引导降级为「定制一件类似的」+「聊聊来龙去脉」 |
| 其他作品的推荐位 | 自动排除已售出作品，不再把它推给客户 |
| 搜索引擎结构化数据 | 从 `InStock` 改为 `SoldOut`，不会误导搜索流量 |

### 重新上架 / 改错了

把 **「已售出」** 的勾**取消**再保存即可，作品恢复为在售，同样 2-3 分钟上线。

### 新增一幅现货作品

**新增作品仍需找 AI**——作品的题字、释文、材质、价格、图片属于正文内容，在代码里（`src/data/content.ts`）。
新增后 AI 会同时在「现货上下架」里建好对应的一行，之后售出/上架就都能自助操作。

> 顺带说明：**礼品**（另一个板块「产品与礼品」）本身就有「发布」开关，取消勾选即下架，那一条链路完全自助。

## 三·E、线索怎么处理（三类表单 + 响应时限）

站上所有表单提交都会进云端的同一张 `leads` 表，每条记录带 `form_type` 区分来源。

### 三类线索 + 订阅

| 来源表单 | `form_type` | 说明 |
|---|---|---|
| 快速留言（联系页 / 首页「与我们聊聊」） | `quick_message` | 最轻的入口，问一句就走 |
| 定制委托（定制创作页 / 送礼建议） | `commission` | 有明确定制意向，含情境、预算线索 |
| 企业礼赠需求 | `business_gift` | B 端，含人数、场合、时间 |
| 心愿单提交 | `wishlist` | 客户把作品加入心愿单后提交 |
| 邮件订阅 | （存 `subscribers` 表） | 仅邮箱，不产生待办 |

每条线索记录：`name`（称呼）、`contact`（联系方式）、`payload`（表单里填的全部内容）、`status`（处理状态，默认 `new`）、`created_at`（提交时间）。
`payload` 里已包含来源页面与来源渠道信息，可据此判断哪条渠道带来了哪类线索。

### 建议的响应时限（**待业主确认**）

> 下表是拟定的建议值，不是已生效的承诺。请业主核定后把「建议」改为正式时限，再对外表述。

| 线索类型 | 建议首次响应 | 理由 |
|---|---|---|
| `business_gift` 企业礼赠 | **24 小时内** | B 端决策周期长，谁先回谁先进入比稿 |
| `commission` 定制委托 | **48 小时内** | 需要看情境与预算，可先给一个方向性回复 |
| `quick_message` 快速留言 | **3 个工作日内** | 意图最轻，回太急反而打扰 |
| `wishlist` 心愿单 | **不需要单独回** | 只作需求记录，用于观察哪几幅被反复加入 |

### 状态流转（建议）

`new`（未处理）→ `contacted`（已联系）→ `quoted`（已报价）→ `won`（成交）/ `closed`（关闭）

> ⚠️ 状态字段（`leads.status`）与提交时间已存在，**但目前没有后台界面**——现阶段需要查数据时找 AI 导出一份。
> 如果想在网站上做一个「线索看板」（按类型/状态/时间查看、改状态），可以立项开发；这不影响表单正常收件。

## 三·F、内容授权与事实边界（发布前先读这条）

站点对外的承诺写在页脚和故事墙上：**「客户故事与图像获得授权后发布」「已确认内容才会公开呈现」「不使用未经核验的客户数量、媒体曝光或合作机构作为背书」**。
后台的默认值就是按这条承诺设的，请不要绕过。

### 两条硬规则

**1. 客户故事：授权与发布是两个开关，缺一不发布。**

| `已获公开授权` | `发布` | 结果 |
|---|---|---|
| ❌ | ❌ | 不发布（默认状态） |
| ❌ | ✅ | **仍然不发布** —— 只勾发布不算数 |
| ✅ | ✅ | 出现在 /stories/ |
| ✅ | ❌ | 存着，暂不公开 |

这不是提醒，是代码里的硬过滤：故事墙只读「已获授权 **且** 已发布」的内容。

**2. 别把「情境示例」写成「客户原话」。**

介绍一位客户的真实经历、引用原话、或展示作品与客户的对应关系，都需要先拿到本人同意。
没有授权时，可以写「按常见情境整理」的通用描述，但不要用第一人称口吻写成某人说过的话。
同理：不要写没有依据的客户数量、复购率、媒体报道或合作机构——页脚已明确承诺不做这类背书。

### 图片也属于「内容」

作品实拍、客户空间照、聊天截图都一样。涉及客户居家环境或私人信息的图片，授权前不要上传。
站上图片分三类，上传时请说清是哪一类，不要混用：**实拍**（作品本身）、**空间示意**（AI/示例场景，页面会标注「空间示意」）、**授权案例**（客户同意公开的真实场景）。

## 五、如何增加动态画面（提升访问体验）

按「投入小 → 效果大」排序，都可以让 AI 实现：

1. **滚动浮现**（已内置）：页面元素随滚动轻轻浮现，移动端同样生效。
2. **首页视频/动图背景**：一段 5~10 秒循环的书写/茶室实拍（手机横拍即可），
   转成 MP4/WebM 放首页顶部，安静但有生命力。**最推荐**。
3. **微交互**：卡片悬停轻抬、印章按钮按压回弹、图片缓慢变焦——细节质感。
4. **横向滚动画廊**：作品/案例图左右滑动浏览，移动端手势友好。
5. **加载与过渡**：页面切换淡入、图片模糊占位→清晰，减少「跳」的感觉。
6. **节气动态元素**：首页按节气切换一句题字动画（如朱砂印章盖章动效）。

> 原则：动态为「安静的服务」，不做满屏动效；动图统一提供移动端压缩版（<2MB）。

## 六、常见问题

- **后台打不开/登录报错**：先确认 `.env` 的 4 个值已配置到 Cloudflare；
  再检查 GitHub App 是否安装到仓库、callback URL 是否含线上地址。
- **保存了但网站没变**：① 等 2-3 分钟 ② 查 GitHub 仓库 Actions 页是否构建成功
  ③ 手机端下拉强刷（有缓存）。
- **误删了内容**：GitHub 提交历史都在，可回滚；或找 AI 恢复。
- **多人协作**：所有有仓库写权限的 GitHub 账号都能登录后台，改动互相可见。
