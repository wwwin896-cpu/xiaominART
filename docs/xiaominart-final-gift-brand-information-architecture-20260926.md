## 一、最终业务定位

网站不是独立电商收银台，也不是单纯艺术作品展示站，而是小民艺术的：

1. **品牌信任中心**：解释品牌是谁、为什么做这样的礼物。
2. **礼赠决策中心**：帮助用户按对象、场合、预算找到礼物。
3. **搜索流量中心**：承接百度、Google、微信搜一搜和小红书外部搜索访问。
4. **内容种草承接中心**：接住小红书笔记、视频和达人推荐带来的用户。
5. **小程序成交导流中心**：将高意向用户导向微信小程序完成下单。
6. **定制与企业礼赠入口**：承接高客单价定制、批量采购和企业客户咨询。

核心链路：

```text
小红书笔记 / 达人种草 / 搜索结果
              ↓
      网站专题页或礼品详情页
              ↓
   理解品牌 → 选择对象/场合/预算 → 查看礼物细节
              ↓
  普通商品：进入微信小程序下单
  不确定：获取送礼建议
  高客单：发起定制咨询
  企业客户：提交企业礼赠需求
              ↓
      小程序成交 / 微信持续运营 / 复购与转介绍
```

## 五、用户运营路径

### 5.1 小红书种草路径

```text
小红书笔记 / 视频
│
├── 场景型内容：乔迁、生日、茶室、书房
│   └── 进入对应场合页或场景专题页
│
├── 产品型内容：礼盒、包装、手写贺卡、开箱
│   └── 进入具体礼品详情页
│
├── 方法型内容：送长辈、送客户、预算选择
│   └── 进入对象页、场合页或礼品筛选页
│
└── 品牌型内容：升斗小民、书写过程、品牌故事
    └── 进入品牌故事或 Journal

页面内统一提供：
├── 查看礼物细节
├── 获取送礼建议
├── 加入礼物清单
└── 微信小程序下单 / 查看更多
```

小红书内容不要全部导向首页。每一篇笔记都应对应一个具体落地页，形成：

```text
笔记主题 = 页面主题 = 搜索关键词 = CTA
```

### 5.2 微信小程序成交路径

```text
网站礼品详情页
│
├── 普通礼品
│   └── 小程序商品详情 / 下单
│
├── 礼盒或组合方案
│   └── 小程序礼盒详情 / 下单
│
├── 用户不确定
│   └── 网站送礼建议 / 微信咨询
│
└── 高客单价、企业或特殊需求
    └── 网站咨询表单 / 企业需求提交
```

网站不承担支付和订单状态，网站只负责：

- 解释产品。
- 建立信任。
- 提供选择建议。
- 将用户导入正确的微信小程序页面。

实际小程序路径、二维码和商品 ID 不硬编码在模板中，应由 Keystatic 或站点配置管理。

### 5.3 渠道参数和效果追踪

所有小红书和外部推广链接统一使用渠道参数，例如：

```text
?utm_source=xiaohongshu&utm_medium=note&utm_campaign=housewarming&utm_content=cover-01
```

建议后台管理：

- 渠道来源。
- 内容主题。
- 推广活动。
- 小程序目标页面。
- CTA 文案。
- 二维码版本。

不得把临时渠道参数写死在页面组件中；应允许运营在后台更新。

## 七、SEO 架构

### 7.1 SEO 页面类型

| 页面类型 | 示例关键词方向 | 页面职责 |
|---|---|---|
| 品牌页 | 小民艺术、东方日常之礼 | 品牌认知与信任 |
| 私享礼遇 | 私享礼遇、东方礼物、艺术礼品、文化礼物 | 核心品类入口 |
| 场合页 | 生日礼物、乔迁礼物、开业礼物 | 承接明确需求 |
| 对象页 | 送长辈礼物、送客户礼物、送老师礼物 | 承接关系型需求 |
| 产品页 | 具体礼盒、书法礼物、茶室礼物 | 高意向详情和转化 |
| 内容页 | 如何选礼、送礼寓意、包装建议 | 长尾流量与教育 |
| 企业页 | 企业礼赠、商务伴手礼、批量定制 | B2B 询价 |

### 7.2 每个 SEO 落地页必须具备

- 唯一 title。
- 唯一 description。
- 清晰 H1。
- 面向用户问题的正文。
- 相关礼品列表。
- 相关场合/对象链接。
- FAQ。
- 面包屑。
- 图片 alt。
- 规范 canonical。
- 结构化数据，按页面类型使用 Product、Article、FAQPage、Organization 或 BreadcrumbList。
- 明确 CTA。

### 7.3 内链逻辑

```text
Journal 文章
  → 场合页 / 对象页
  → 礼品列表
  → 礼品详情
  → 小程序下单或咨询

礼品详情
  → 适合场合
  → 适合对象
  → 相关 Journal
  → 相关礼盒
  → 小程序下单

场合页 / 对象页
  → 推荐礼品
  → 选择建议
  → FAQ
  → 获取送礼建议
```

SEO 不是单独做一批文章，而是让每篇内容都能进入礼品选择和成交路径。

### 内容模型原则

- 品牌 Logo SVG 属于代码资产，不允许后台直接修改文件内容。
- 产品、场合、对象、价格、交付、包装和渠道链接必须后台可维护。
- `published: false` 的内容不得出现在前台。
- 未获授权的客户案例不得公开。
- 小程序商品链接不写死在组件中。
- 任何价格、交付和售后承诺必须有明确来源并可追溯。

## 十、批次 0 补充决策与执行约束

本节根据项目评审意见补充，并作为后续开发的正式验收依据。

### 10.1 “场景与灵感”的最终归属

“场景与灵感”不是普通礼品详情页的附属段落，也不作为一级主导航。它定位为独立的 **SEO + 小红书种草内容集群**，同时服务礼品决策：

```text
场景与灵感内容集群
├── 独立 SEO 页面：书房、客厅、茶室、玄关、企业空间
├── 礼赠场景页：生日、乔迁、节日、感谢、开业、周年
├── 包装与开箱专题
├── 书写与器物搭配专题
└── 小红书专题承接页
```

用户入口关系：

- 从小红书或搜索进入场景页。
- 场景页链接到相关“选礼指南”页面和具体“私享礼遇”详情。
- 礼品详情页只保留与当前礼物直接相关的场景摘要和推荐链接。
- 场景内容不重复复制完整产品详情，避免 SEO 内容重复和维护分叉。

因此，场景内容既有独立流量价值，又不会稀释四项主导航。

### 10.2 数据追踪和效果分析

第一阶段只接入不涉及支付隐私的页面行为追踪；小程序订单数据仍以小程序后台为准。网站事件命名统一采用可迁移的事件模型：

| 事件 | 触发位置 | 业务含义 |
|---|---|---|
| `gift_guide_view` | 选礼指南 | 用户进入选礼决策页 |
| `gift_filter_apply` | 预算 / 场合 / 对象筛选 | 用户开始明确需求 |
| `gift_detail_view` | 私享礼遇详情 | 高意向商品浏览 |
| `mini_program_click` | 小程序按钮 / 二维码 | 关键导流转化 |
| `gift_advice_click` | 获取送礼建议 | 咨询型线索 |
| `custom_inquiry_start` | 定制入口 | 高客单意向 |
| `business_inquiry_submit` | 企业礼赠表单 | B2B 线索 |
| `channel_landing_view` | 小红书专题页 | 渠道承接效果 |

追踪规则：

- 小红书链接统一保留 `utm_source`、`utm_medium`、`utm_campaign`、`utm_content`。
- 网站只记录匿名访问和点击行为，不在 URL 中放置手机号、微信号或订单信息。
- GA4、百度统计或其他统计工具以实际账号和隐私合规条件为准，未授权前不硬编码测量 ID。
- 关键看板至少观察：渠道来源、落地页、选礼指南停留、筛选使用率、详情页到小程序点击率、咨询开始率和企业提交率。

### 10.3 移动端优先验收

小红书流量默认按移动端优先设计和测试：

- 选礼筛选采用大面积触摸控件，不使用难以操作的窄小下拉项。
- 筛选结果、预算标签和 CTA 支持单手操作。
- 礼品主图使用响应式图片、明确尺寸和懒加载；首屏主图不延迟加载。
- 小程序入口同时提供按钮和二维码降级展示；移动端优先显示按钮，二维码作为辅助。
- 详情页首屏必须能看到礼物名称、适合对象、场合、价格区间和下一步按钮。
- 移动端不得出现横向滚动、底部快捷栏遮挡 CTA 或弹层无法关闭。

### 10.4 内容冷启动最低基线

进入正式推广前，至少准备以下可公开内容；如果真实素材、价格或授权尚未确认，宁可标记为待发布，也不使用虚构信息：

- 6–10 个完整私享礼遇条目。
- 6 个场合 SEO 页面。
- 6 个对象 SEO 页面。
- 8 篇 Journal 种子文章，覆盖送礼方法、东方日常、礼物故事、创作手记四类栏目。
- 3 个已获授权或明确标注“资料整理中”的企业 / 客户故事入口。
- 1 个包装与手写贺卡专题。
- 1 个配送、售后和咨询说明页。

上线后的最低更新节奏建议：每月补充至少 2 篇 Journal 或专题内容；节日和节气活动根据运营计划提前建立专题页。

### 10.5 企业礼赠转化路径

企业礼赠不只设置一个普通联系表单，建议形成分层转化：

```text
企业礼赠落地页
├── 企业礼赠适用场景
├── 礼盒 / 书写 / 器物方向
├── 数量、预算和交付说明
├── 已授权企业案例
├── 企业礼赠方案 PDF 下载（留资钩子，确认文件后上线）
├── 专属联系人 / 邮箱 / 电话（确认后上线）
└── 提交企业需求
```

PDF、联系人和案例信息必须在真实资料确认后发布，不用占位信息制造信任。

### 10.6 风险预案

| 风险 | 预案 |
|---|---|
| Keystatic 或 GitHub 登录异常 | 保留本地内容文件和 Git 历史；后台不可用时不影响已部署前台；恢复后再编辑发布 |
| GitHub 网络波动导致 Vercel 构建失败 | 保留最近一次成功部署；先检查构建日志，修复后重新部署，不删除可用版本 |
| 小程序商品链接失效 | 后台提供链接状态和备用 CTA；失效时降级为获取送礼建议，不显示失效按钮 |
| 产品价格 / 交付信息未确认 | `published: false` 或显示待确认状态，不公开未经确认的承诺 |
| 客户案例未授权 | 不公开图片、姓名和评价；后台单独维护授权状态 |
| 统计工具未授权 | 不注入测量 ID；先保留事件接口和文档，待合规确认后启用 |

## 十一、改造执行顺序

### 批次 0：架构确认

- 确认礼品作为第一业务入口。
- 确认主导航采用“私享礼遇 / 选礼指南 / 企业礼赠 / 品牌故事”，其中选礼指南统一承接场合与对象。
- 确认普通礼品和定制项目分开计价。
- 确认小程序负责支付、订单和库存。
- 确认小红书内容进入具体落地页，而不是全部进入首页。

### 批次 1：内容数据层

- 创建 `src/lib/keystatic.ts`。
- 扩展礼品 schema。
- 新增 occasions、recipients、channel landing pages。
- 迁移现有礼品、场景、Journal 和 FAQ。
- 统一价格和发布状态。

### 批次 2：站点骨架

- 调整主导航和二级菜单。
- 重做首页礼品导向结构。
- 建立私享礼遇中心和选礼指南中心，场合与对象作为选礼指南下的 SEO 子页。
- 建立统一详情页模板。
- 增加小程序导流组件。

### 批次 3：SEO 与渠道承接

- 设置每类页面的 title、description、canonical 和结构化数据。
- 建立 Journal 四类内容栏目。

- 统一 UTM 参数和渠道配置。

### 批次 4：成交与运营

- 接入真实小程序商品链接或二维码。
- 接入咨询表单/邮件通知。
- 接入企业礼赠线索管理。
- 验收移动端筛选、导航和 CTA。
- 验收 SEO、图片、404、结构化数据和部署。

## 十二、项目验收标准

### 品牌

- 首页第一屏明确表达“礼品品牌”。
- 用户不看完整页面也能找到选礼入口。
- 艺术定制是升级服务，不再压过普通礼品。
- Logo、品牌名、艺术家笔名和品牌主张统一。

### 用户体验

- 3 次点击内能从首页进入礼品详情。
- 用户可以按场合、对象和预算选礼。
- 礼品详情解释寓意、包装、贺卡、交付和下一步。
- 小程序下单入口清晰，但不伪造站内支付。
- 移动端导航和筛选无横向溢出。

### SEO

- 核心页面均有唯一 metadata。
- 场合、对象、礼品、Journal 形成内链闭环。
- 小红书每种内容都对应具体落地页。
- 页面有 FAQ、面包屑、alt 和结构化数据。
- URL 稳定，不因营销文案变化频繁改动。

### 运营

- 运营人员可通过 Keystatic 修改礼品、场合、对象、价格说明、包装、交付和渠道链接。
- 产品隐藏可以通过发布状态完成，不删除历史内容。
- 小程序链接、二维码和 UTM 参数可以独立更新。
- 客户案例授权状态可控。

### 技术

- `npm run check` 能完成或有明确的依赖内存解决方案。
- `npm run build` 成功。
- Vercel Production 成功部署。
- 关键页面、资源和后台路由可访问。
- 不提交密钥，不在代码中写死小程序凭据。
