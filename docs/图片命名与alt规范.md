# 小民艺术官网 · 图片命名与 alt 规范

> **用途**：新图入库时照此执行。回答两个问题 ——
> ①「alt 为空、文件名是哈希」这项工作到底完成了没有？
> ② 以后图片该怎么命名才有利于 SEO？
>
> **核查日期**：2026-10-09 · **核查对象**：线上 https://xiaominart.com （73 页 / 376 张 img）

---

## 一、结论先说：这项工作的实际状态

| 诊断项 | 诊断结论 | 实测结果 | 判定 |
|---|---|---|---|
| 文件名为哈希值 | 影响 SEO | **全站 0 个哈希式文件名**，全部为语义化英文（`story-du-shu-gu-xiang.jpg`、`hero-shiguwen-light.jpg`） | ❌ **不成立** |
| alt 属性为空 | 影响 SEO | 376 张 img 中 **alt 为空的有 3 张**，且均在**装饰性图**上（正确写法） | ⚠️ **部分成立，但属误报** |

**为什么 3 张空 alt 是正确写法而不是缺陷**：

那 3 张是首页横幅的**背景氛围图**（`hero-shiguwen-light.jpg` 等），作用是铺底色、透出文字，
**不承载任何信息**。无障碍规范（WCAG）明确规定：

> **纯装饰性图片应当使用 `alt=""`（空字符串），而不是填一段描述。**
> 因为屏幕阅读器会跳过空 alt，这是告诉辅助技术「这张图可以忽略」的标准方式。
> 反过来，给装饰图硬填描述反而会**干扰**屏幕阅读器用户。

所以这 3 张不是「忘了写」，是**刻意留空且写法正确**。

**但核查中发现一个真实的次要不一致**（详见第四节），值得修。

## 二、图片命名规范（以后新增图片照这个来）

### 2.1 核心格式

```
<类别前缀>-<内容描述>-<可选尺寸后缀>.<扩展名>
```

全小写 · 单词间用连字符 `-` · 只用 ASCII 字母数字 · **绝不用中文、空格、下划线、大写**

### 2.2 按类别的前缀约定（沿用现有目录结构）

| 目录 | 前缀 | 示例 | 说明 |
|---|---|---|---|
| `assets/stories/` | `story-` | `story-du-shu-gu-xiang.jpg` | 客户故事，用**作品名拼音** |
| `assets/scenes/` | 无前缀，场景直述 | `living-room-round-seal.jpg`<br>`cinnabar-bedroom.jpg` | 空间 + 元素 |
| `assets/craft/` | `step-N-` | `step-1-writing.jpg` | 工艺步骤，**带序号** |
| `assets/brand/` | `xiaominart-` | `xiaominart-logo.png` | 品牌资产 |
| `assets/images/` | 用途直述 | `wechat-qr.jpg`<br>`og-image.png` | 功能图 |

### 2.3 尺寸后缀（由 `scripts/gen-webp.mjs` 自动生成，**不要手写**）

```
xiaominart-logo.png          ← 你只放这一个原图
xiaominart-logo.webp         ← 脚本自动生成（基础副本）
xiaominart-logo-600.webp     ← 脚本自动生成（600px 响应式变体）
```

> ⚠️ **手动放图时只放原图**（`.jpg` / `.png`），WebP 与尺寸变体由构建脚本自动产出。
> 脚本规则（`scripts/gen-webp.mjs:15-19`）：基础副本上限 1600px；
> `-600` 变体要求源图 ≥900px、`-1000` 变体要求源图 ≥1300px，**绝不放大**。

### 2.4 关键词策略（这是 SEO 的关键）

**文件名是图片 SEO 权重最高的位置之一**（仅次于 alt）。命名时把**用户会搜的词**放进去。

| ✅ 好的命名 | ❌ 差的命名 | 为什么 |
|---|---|---|
| `study-desk-scroll.jpg` | `IMG_2831.jpg` | 相机默认名，零关键词 |
| `cinnabar-bedroom.jpg` | `微信图片_20260901.jpg` | 中文+时间戳，URL 编码后变乱码 |
| `story-shou-yuanguang.jpg` | `a3f9b2c1e8d7.jpg` | 哈希名，搜索引擎读不出内容 |
| `step-2-mounting.jpg` | `step2.jpg` | 缺语义，不知道是什么步骤 |

**关键词优先级**（从左到右，重要的放前面）：

```
① 主体/场景  ② 材质/形式  ③ 用途
study-desk-scroll  =  书房 + 案头 + 卷轴
cinnabar-bedroom   =  朱砂 + 卧室
```

**中文内容的英文命名对照**（本项目实际用词）：

| 中文 | 英文 | 中文 | 英文 |
|---|---|---|---|
| 书房 | study | 卷轴/竖幅 | scroll |
| 客厅 | living-room | 横幅 | banner / hengjuan |
| 卧室 | bedroom | 小镜框 | frame |
| 茶室 | tearoom | 小品 | xiaopin |
| 玄关 | entry | 装裱 | mounting |
| 朱砂 | cinnabar | 包装 | packaging |
| 山水 | shanshui | 题跋 | inscription |

> 作品名（如「读书古香」）用**拼音**：`du-shu-gu-xiang`。
> 不要硬译英文，拼音在中文 SEO 场景下更准确、也更不易歧义。

### 2.5 命名检查清单（放图前逐条过）

- [ ] 全小写，无中文、无空格、无下划线
- [ ] 用连字符 `-` 分隔单词（**不是** `_` —— 连字符是 Google 官方推荐的分词符）
- [ ] 文件名能读出「这是什么」（不是 IMG_1234 / 微信图片 / 哈希串）
- [ ] 包含 1–3 个用户可能搜索的关键词
- [ ] 长度 ≤ 60 字符
- [ ] 只放**原图**，WebP 变体交给脚本

## 三、alt 属性写法规范

### 3.1 判断流程

```
这张图承载信息吗？
├─ 否（纯装饰：背景、分隔线、氛围图）→ alt=""  （空字符串，必须写 alt 属性）
└─ 是（内容图：作品、案例实拍、步骤图）
   └─ alt="<具体描述>"，写清「画面里有什么、在什么场景」
```

### 3.2 内容图 alt 的写法（本项目已达标，供参照）

**多要素对比式描写** —— 这是本站现有的写法，质量很高，继续保持：

```
alt="现代中式客厅的墨绿墙上，斗柜上方挂着「中家赞」竖幅书法，旁有落地灯与扶手椅"
alt="书房木质案头立着「永奇嗜读戏」竖幅小镜框，旁有绿玻璃台灯、钢笔与盆栽"
```

**好在哪**：包含**空间（客厅/书房）+ 陈设位置（墙上/案头）+ 作品名 + 周边物件**。
用户搜「客厅挂什么书法」「书桌摆件」都能命中。

### 3.3 alt 的禁忌

| ❌ 不写 | 原因 |
|---|---|
| `alt="图片"` / `alt="image"` | 等于没写，还占位置 |
| `alt="小民艺术"` | 品牌名堆砌到每张图，会被判作弊 |
| `alt="作品1.jpg"` | 文件名不是描述 |
| 不给装饰图写 `alt=""` 而省略 alt 属性 | 屏幕阅读器会念出文件名，体验更差 |
| alt 与周围正文完全重复 | 冗余，屏幕阅读器用户要听两遍 |

## 四、核查中发现的一个真实待修项

在首页 `src/pages/index.astro` 发现一处**语义不一致**（不是上面那 3 张空 alt 的锅）：

**问题**：三张 hero 图的容器写死在 HTML 里是 `aria-hidden="true"`，但脚本会在切换轮播时
把它改成 `aria-hidden="false"`（`index.astro:64`）：

```js
slides.forEach((slide, i) => {
  slide.classList.toggle('is-active', i === current);
  slide.setAttribute('aria-hidden', i === current ? 'false' : 'true');
});
```

**后果**：第 1 屏被激活时，外层 `hero-slide` 变成 `aria-hidden="false"`（对辅助技术**可见**），
但里面的 `<img alt="">` 是空的 —— 于是「可见的容器里有一张无描述的图」。

**定性**：
- 对 **SEO**：几乎无影响（装饰图本就不该抢关键词，Google 能理解空 alt）
- 对 **无障碍**：属轻度瑕疵，屏幕阅读器在该容器内会跳过这张图（可接受），但语义不够干净

**建议修法**（二选一，改动极小）：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | 给 `hero-media` 的 `aria-hidden="true"` 保持**写死不被脚本改动**，只让 `hero-slide` 的外层切换 aria-hidden | 装饰图永久对辅助技术隐藏，语义最干净 |
| B | 给这三张图填上有意义的 alt（如「石刻文字特写，浅纸底色」） | 但它们确实是背景氛围图，填描述反而多余 |

> **优先级**：低。这是打磨项不是缺陷项，不影响 SEO 表现。
> 助手可随时执行方案 A，改动约 3 行。

## 五、给你的一句话操作指引

**以后新图入库，照这个来**：

```
1. 命名：study-desk-scroll.jpg
         ↑场景  ↑主体  ↑形式     全小写、连字符、英文、有语义

2. 放图：只放原图到对应目录（如 public/assets/scenes/），
         WebP 和 -600/-1000 变体由构建脚本自动生成，别手写

3. 写 alt：看这张图有没有信息
   ├─ 有（作品/案例/步骤）→ alt="现代中式书房，木案上立着竖幅书法，旁有台灯与盆栽"
   └─ 没有（纯背景/氛围） → alt=""   ← 空着是对的，别硬填

4. 检查：文件名里能不能读出「这是什么」？读不出就重命名
```

**最重要的一条经验**：文件名和 alt 里放进**用户真会搜的词**（书房、客厅、朱砂、竖幅、乔迁礼物），
而不是品牌名或「图片1」。搜索引擎读不懂图片像素，只能读你给的文字。
