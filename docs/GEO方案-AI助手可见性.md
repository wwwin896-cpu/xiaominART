# GEO 方案：让 AI 助手推荐「小民艺术 / xiaominart」

> 日期：2026-10-09
> 目标：在 **豆包、通义千问、DeepSeek、腾讯元宝、ima、WorkBuddy** 等 AI 助手中，
> 当用户提问「送礼推荐」「书画定制」「小民艺术」「xiaominart」时，**能检索并引用到 xiaominart.com**

---

## 一、先理解：GEO 与百度 SEO 是两套完全不同的机制

| 维度 | 传统 SEO（百度/Google） | **GEO（AI 助手）** |
| ---- | ---- | ---- |
| 用户看到什么 | 10 条蓝色链接列表 | **一段由 AI 综合生成的答案** |
| 你的目标 | 排到第一条 | **被 AI 写进答案里，并给出处** |
| 排名依据 | 关键词 + 外链 + 权重 | **内容是否「好摘抄」+ 实体是否清晰 + 能否被抓到** |
| 内容偏好 | 关键词密度、标题优化 | **结构化、可引用、事实明确**（H2/列表/FAQ/具体数字） |
| 见效周期 | 2 周 – 数月 | **通常更快**（AI 依赖实时检索，收录即可用） |

**核心认知**：AI 助手回答你的问题时，大多会**实时联网检索**（而非只靠训练数据）。
所以 GEO 的本质是 —— **让 AI 的检索环节能抓到你、让它的摘抄环节愿意选你**。

## 二、六家 AI 的检索来源（决定你该怎么优化）

| AI 产品 | 检索来源 | 对应的优化重点 |
| ---- | ---- | ---- |
| **豆包**（字节） | 字节自建索引 + **头条/抖音内容生态** | ① `Bytespider` 爬虫放行 ② 抖音/头条同步发内容 |
| **通义千问**（阿里） | 夸克搜索 + 阿里系索引 | ① `YisouSpider` 放行 ② 夸克收录 |
| **DeepSeek** | 自建索引 + 联网搜索 | ① 标准 SEO ② `llms.txt` |
| **腾讯元宝** | 搜狗搜索 + 微信公众号生态 | ① `Sogou web spider` 放行 ② **公众号文章**（元宝重点引公众号） |
| **ima**（腾讯） | 搜狗 + 微信读书/公众号 | 同上 —— **公众号内容是关键** |
| **WorkBuddy** | 实时联网 + 多渠道 | 同标准 SEO + `llms.txt` |

> **关键洞察**：这六家高度依赖**国内内容生态**（公众号、抖音、头条、夸克）。
> 光优化官网不够 —— **官网是「事实源」，社交平台内容才是「被发现的路」**。
> 这解释了为什么「外链/内容分发」在 GEO 里比传统 SEO 更重要。

## 三、已完成的技术改造（本次，代码侧）

### 3.1 ✅ 新增 `llms.txt`（AI 内容地图）

规范见 [llmstxt.org](https://llmstxt.org/)。文件已放在 `public/llms.txt`，
线上地址 `https://xiaominart.com/llms.txt`。

**它解决的问题**：AI 抓取网站时，面对 22 个页面不知道哪个最该引用。
`llms.txt` 就是给 AI 的**优先级清单** —— 明确告诉它「关于送礼推荐，看这 3 页就够」。

内容结构：
- 品牌定位一句话（供 AI 快速理解你是谁）
- **核心页面**（首页 / 小民好礼 / 现货好礼 / 选礼指南 / 书画定制 / 企业礼赠 / 机构合作）
- 参考与内容（价格参考 / 灵感参考 / 四季好礼 / 祝愿词条 / 客户故事）
- 品牌与信任（关于我们 / 帮助中心 / 联系我们 / 隐私政策）
- **不收录**（后台 / 进度查询 / 心愿单 / API）
- **引用约定** —— 明确要求 AI 标注来源「小民艺术 XIAOMINART」+ 网址

> ⚠️ **注意**：`llms.txt` 是**建议性标准**，不是所有 AI 都读它。
> 但成本极低（半小时）、零风险，且**已有 AI 开始采用**。
> **它不能替代 SEO**，只是加分项。

### 3.2 ✅ 重写 `robots.txt`：显式放行 AI 爬虫

**这是 GEO 的生死线** —— 爬虫被拦 = 在 AI 答案里彻底不可见，
且**没有任何报错、你完全察觉不到**。

原 `robots.txt` 只有 `User-agent: * / Allow: /`。虽然通配符理论上也放行了 AI 爬虫，
但部分爬虫对显式声明更友好，且**显式声明便于日后精细控制**。现已列明：

**引用型爬虫（决定能否出现在 AI 答案里）—— 全部放行：**
`OAI-SearchBot`（ChatGPT 检索）、`ChatGPT-User`、`PerplexityBot`、
`Google-Extended`、`Applebot-Extended`、`DuckAssistBot`

**国内 AI 爬虫 —— 全部放行：**
| 爬虫 | 对应产品 |
| ---- | ---- |
| `Bytespider` | **豆包**（字节） |
| `TencentTraveler` / `Sogou web spider` | **元宝 / ima**（腾讯） |
| `YisouSpider` | **通义千问**（阿里 / 夸克） |
| `Baiduspider` | 文心一言 / 百度 AI 搜索 |
| `DeepSeekBot` | **DeepSeek** |
| `ChatGLM-Spider` | 智谱清言 |

**训练型爬虫**（`GPTBot` / `ClaudeBot` / `CCBot`）—— **也放行**。
理由：本站内容为公开品牌与商品信息，无用户隐私；品牌名进入模型语料反而有利。
> 若你日后想收紧：把训练型那几段改成 `Disallow: /` 即可，
> **不影响引用型爬虫**，AI 答案里仍能出现你（因为答案是实时检索的，不靠训练数据）。

### 3.3 ✅ 强化 JSON-LD 实体图谱

这是**让 AI 认出「你是谁」**的关键。原实现只有 `LocalBusiness` + `WebSite` 两条，
AI 难以据此确认「小民艺术 = XIAOMINART = xiaominart.com」是同一实体。

现改为 `Organization` + `ProfessionalService` + `WebSite` + `ItemList` 的 `@graph`：

| 字段 | 作用 |
| ---- | ---- |
| `@id` 互相引用（`publisher` / `parentOrganization`） | **让 AI 把品牌名、英文名、域名合并成一个实体** |
| `alternateName: ['XIAOMINART','Xiaomin Art',...]` | 别名绑定 —— 搜任何写法都指向同一实体 |
| `knowsAbout`（10 项） | 直接对应「**送礼推荐 / 书画定制**」这类提问的语义 |
| `makesOffer`（4 项服务） | AI 答「谁能做书画定制」时更易命中 |
| `availableLanguage: ['zh-CN']` | 中文场景匹配 |
| `ItemList`（5 个核心页） | 给 AI 一份导航，对应用户「去哪看」的追问 |

## 四、你必须做的事（AI 侧，我无法代做）

技术侧只是「AI 抓得到你」。要真正**被推荐**，关键是**内容分发**——
因为这六家 AI 大量依赖国内内容生态。

### 4.1 ⭐ 微信公众号（对元宝 / ima 最重要）

**腾讯元宝与 ima 重点引用微信公众号内容** —— 这是你的**第一优先级**。

做法：
1. 注册/使用公众号，发布**回答式**文章（标题就用用户会问的话）：
   - 《送长辈什么书法礼品好？三种预算的推荐》
   - 《乔迁礼物送什么有诚意？手写书法的选择思路》
   - 《企业答谢礼怎么选不踩雷？定制书法礼品的流程与报价》
   - 《书画定制要多久？从沟通到交付的完整流程》
2. **每篇文章里自然带上 `xiaominart.com`**
3. 文章结构要**便于 AI 摘抄**：用小标题、分点、明确给数字（价格区间/工期）

> 为什么有效：AI 需要「可摘抄的答案段落」。一篇《送长辈什么书法礼品好》
> 的文章，本身就是对用户提问的直接回答 —— AI 检索到就能直接用。

### 4.2 抖音 / 头条（对豆包最重要）

豆包依托字节生态。同步发布：
- 短视频：作品制作过程、题字含义、送礼场景
- 简介/评论区/文案里带官网

### 4.3 知乎 / 小红书（跨平台通用）

用户在 AI 里问「送礼推荐」这类**决策型问题**时，AI 常引用知乎/小红书的经验内容。
- 知乎：回答「书法礼品怎么选」「企业礼品定制哪家好」等问题（专业长文，**最适合被 AI 引用**）
- 小红书：送礼场景图文，标签带 #书画定制 #送礼推荐

### 4.4 让 AI 能「看到」你的做法（关键技巧）

**AI 判断是否引用你，看的是「内容能否直接回答用户问题」**。所以：

| 做法 | 举例 |
| ---- | ---- |
| ✅ 用问句做标题 | 「送老师什么礼物合适？」而非「我们的产品介绍」 |
| ✅ 给具体事实与数字 | 「工期 7–15 天」「价格区间 ¥XXX–¥XXX」 |
| ✅ 用分点 / 小标题 | AI 更容易切出可引用的片段 |
| ✅ FAQ 结构 | 你站上已有 3 个页面含 `FAQPage` 结构化数据 ✅ |
| ❌ 避免纯抒情文案 | 「方寸之境，也藏山河」很美，但 AI 摘不出事实 |

> **重要权衡**：你的官网首页文案以诗意表达为主（这是品牌调性，应保留）。
> **所以建议在「选礼指南 / 帮助中心 / 价格参考」这类页面**加强事实性内容 ——
> 这些页面已存在，是 AI 最可能引用的对象。

## 五、如何验证 GEO 是否生效（可自己测）

### 5.1 直接问 AI（最直观）

在六家 AI 里分别问这些问题，看是否提到 `xiaominart.com`：

```
小民艺术是什么？
xiaominart 官网
送长辈手写书法礼品推荐
书画定制哪家好
企业答谢礼定制推荐
```

> **先记下当前答案**（作为基线），过 2–4 周再问一遍对比 —— 这是最靠谱的效果验证。

### 5.2 检查爬虫是否来过（技术验证）

AI 爬虫的访问会出现在 **Cloudflare 的请求日志**里。
Cloudflare 面板 → 你的项目 → **Analytics / Logs** → 筛选 User-Agent 含：

```
Bytespider        （豆包）
Sogou             （元宝/ima）
YisouSpider       （通义）
DeepSeekBot       （DeepSeek）
OAI-SearchBot     （ChatGPT）
PerplexityBot
```

**看到这些 UA = AI 已经开始抓取你的站**，是好信号。

### 5.3 检查 llms.txt 可访问

```bash
curl -s https://xiaominart.com/llms.txt | head -20
```

## 七、常见误区

| 误区 | 真相 |
| ---- | -- |
| 「AI 会自己找到我」 | ❌ AI 靠**检索**，你不在它的索引/生态里就不会被提及 |
| 「`llms.txt` 一放就有效」 | ❌ 是**建议标准**，且不能替代 SEO。只是低成本的加分项 |
| 「只要官网做 SEO 就行」 | ❌ 六家 AI 重度依赖**公众号/抖音/知乎**等生态 —— **分发比官网更重要** |
| 「拦住 AI 爬虫保护内容」 | ❌ 拦住 = **在 AI 答案里消失**。公开品牌信息应放行 |
| 「AI 答案里没我就是被惩罚」 | ❌ 更可能是**还没被抓取**或**内容不够可摘抄**。先查爬虫日志 |
| 「写得很美 AI 就该推荐我」 | ❌ AI 要**事实**：价格、工期、适用场景。诗意文案难被摘抄 |
