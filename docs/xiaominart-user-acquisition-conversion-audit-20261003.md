# xiaominART 官网普通用户获客与转化审计

日期：2026-10-03  
审计范围：`https://www.xiaominart.com/` 及首页、礼品详情、选礼、艺术家、故事、联系、企业礼赠、灵感和 Journal 入口  
审计视角：首次访问的普通用户，不假设用户了解品牌、书法、面塑或定制流程

## 一、结论先行

当前网站最主要的问题不是审美，而是转化链路没有完全闭合：

```text
看到网站
→ 知道小民艺术能做什么
→ 找到适合自己的礼物或服务
→ 相信作品、交付和联系是真实可靠的
→ 愿意留下有效联系方式
```

目前已确认的高优先级问题：

1. `/shop/` 直接返回 404，用户从“现货 / 购物”入口会遇到断路。
2. 首页没有在首屏明确呈现两位艺术家、书法作品、非遗面塑和“现货 / 定制 / 企业合作”的区别。
3. 首页缺少首屏行动入口，用户要滚动很久才看到咨询 CTA。
4. 首页展示“真实故事”，但故事归档页明确为空，且当前没有公开授权证据，容易造成信任疑问。
5. `/about/` 写着“不卖现货”，与当前“私享礼遇”、礼品卡片和用户已经确认的“手写现货”方向冲突。
6. 企业礼赠表单提交后只在本机生成草稿，不会进入团队后台，属于实际获客线索丢失风险。
7. 详情页有大量具体材质、规格、包装证书和交付时间表述，但项目 README 仍将这些信息列为待业主确认项，存在事实与承诺风险。
8. `/journal/` 实际返回品牌介绍内容，内容架构和 SEO 入口失配。
9. 联系页没有直接可用的官方社交账号或微信入口，只能通过邮件或表单留下微信号，普通用户的即时沟通成本较高。
10. 移动端底部“我的”实际链接到 `/gifts/`，不像用户理解的“我的”，会造成导航认知错误。

## 二、普通用户实际路径诊断

### 路径 A：第一次认识品牌

```text
首页首屏 → 继续下滑 → 四类礼物 → 定制故事 → 共创流程 → 联系
```

问题：

- 首屏文案很有氛围，但用户第一眼不容易知道“可以买什么、能否定制、是否有面塑、如何开始”。
- 首页当前首屏只有轮播图、标题和说明，没有“看现货”“送礼建议”“定制咨询”三个直接入口。
- 视觉气质先于产品和服务解释，适合品牌熟客，不够适合广告或小红书首次落地用户。
- 首页源码中的首屏轮播每 6 秒自动切换，没有明显暂停控制，也没有首屏 CTA；见 [`src/pages/index.astro:23-67`](../src/pages/index.astro:23)。

### 路径 B：用户想买一件现成礼物

```text
导航“私享礼遇” → /gifts/ → 礼品卡片 → 详情 → 获取送礼建议
```

问题：

- 入口名称是“私享礼遇”，首页又称“心意之选”，详情页使用“小民好礼”，用户可能不确定这些是否都是同一个商品入口。
- 详情页显示价格区间，但同时提示小程序链接尚未配置，用户无法完成购买，只能咨询。
- “心意起点约 ¥300 / ¥800”需要明确说明是否包含作品、装裱、包装、贺卡和配送，否则用户会把它理解为最终价格。
- 现货产品没有明确的“有货 / 预售 / 仅供参考 / 需定制”标签。
- `/shop/` 返回 404；任何把它理解为“手写现货”或商品总入口的用户都会中断。

### 路径 C：用户想按场合选礼

```text
选礼指南 → 选择场合或对象 → 作品 → 咨询
```

问题：

- 当前抓取到的 `/gift-guide/` 主要是标题和 FAQ，没有明显的场合卡片、对象卡片或四个手写现货主题入口。
- 普通用户仍要自己理解“节日、生日、谢师、开业、乔迁”等场景和四个主题之间的对应关系。
- 选礼页应该是降低决策成本的核心页面，但当前更像说明页，不像决策工具。

### 路径 D：用户想了解艺术家和文化厚度

```text
首页 / 品牌故事 → 艺术家 → 作品或定制
```

问题：

- 两位艺术家已有独立页面，但页面仍有“落地实景图整理中”“经历与展览信息将随创作笔记持续呈现”等占位内容。
- 对升斗小民而言，古文字、字游记、书写方法等差异化优势还没有被完整讲清楚。
- 对非遗小宁而言，面塑、儿童话本插画、博物馆讲解、文创和场景还原之间的能力关系还不够清晰。
- 艺术家页偏“方向参考”，但缺少用户能马上选择的服务入口：个人礼赠、亲子活动、学校活动、博物馆项目、机构合作等。

### 路径 E：企业用户咨询

```text
企业礼赠 → 方案级别 → 场景 → 企业表单 → 等待回复
```

问题：

- 页面前半段表达清楚，但表单提交后只显示“本机生成需求草稿”，没有真实后台接收。
- 源码中企业表单使用 `preventDefault()`，只改写页面提示，不调用统一的 `/api/lead` 线索接口；见 [`src/pages/business-gifts/index.astro:12-14`](../src/pages/business-gifts/index.astro)。
- 页面公开“50 / 100 / 200 份起订”和预算档位，但没有展示一份标准礼品的具体组成、样品流程、交付节点或可下载简报，企业用户仍不知道下一步会发生什么。
- “24 小时联系承诺需待服务流程配置完成后启用”属于内部建设状态，不应长期出现在面向客户的页面。

## 三、P0：必须优先修复的问题

### P0-1｜修复 `/shop/` 404

线上结果：

- `https://www.xiaominart.com/shop/` 返回 `404 / Not found`。
- 页面只提供“看看小民好礼”，没有把用户带到明确的现货入口。

建议：

- 建立 `/shop/` 正式页，作为“手写现货”或现货总入口；
- 页面展示四个主题：
  - 四时一笺 · 节日问候；
  - 墨有呼吸 · 文房雅室；
  - 一点朱砂 · 传情达意；
  - 案上有山 · 风生水起；
- 保留旧 `/gifts/`，并配置清晰的 canonical 与 301 策略；
- 所有首页、导航、灵感页和移动端“礼物”入口统一指向一个明确的现货入口。

### P0-2｜企业表单必须进入真实线索系统

线上结果：

- 企业页面明确写着“当前提交会在本机生成需求草稿”；
- 用户点击提交后不会真正通知项目团队。

源码证据：

- [`src/pages/business-gifts/index.astro:9`](../src/pages/business-gifts/index.astro)
- [`src/pages/business-gifts/index.astro:12-14`](../src/pages/business-gifts/index.astro)
- 统一线索模块已存在于 [`src/scripts/cloud-forms.ts:11-38`](../src/scripts/cloud-forms.ts)，但企业表单没有使用它。

建议：

- 企业表单复用 `submitLead('business_gift', ...)`；
- 增加成功、失败、网络异常三种状态；
- 成功后显示“已收到 / 回复方式 / 预计下一步”，而不是技术实现说明；
- 在后台确认线索可检索、可追踪、可导出；
- 增加隐私同意和反垃圾字段；
- 只有真实接收链路验证完成后，才删除“本机草稿”提示。

### P0-3｜消除“现货 / 不卖现货”冲突

当前线上冲突：

- 导航是“私享礼遇”；
- 首页展示四类礼物和价格起点；
- 详情页提供“获取送礼建议”；
- `/about/` 却写着“因此 XIAOMINART 不建立一个现货画廊”，并明确“01 不卖现货”。

建议采用一个统一表述：

> 手写现货：已完成或已整理好的作品方向，可先看主题与礼物场景；  
> 定制手写：从人物、场合或一句话开始重新创作；  
> 具体库存、价格、装裱和交付，以确认页面为准。

在真实商品链路准备好之前，不要把“现货”写成可以立即支付购买，也不要写成完全“不卖现货”。

### P0-4｜处理首页“真实故事”的证据边界

首页写着“每一份心意背后，都有一段真实的故事”，并把四个案例标为“灵感源自真实故事”。但 `/stories/` 页面同时写着“故事墙正在留白”，说明第一批作品完成授权后才公开。

这会让普通用户产生两个疑问：

- 首页的故事是否真实发生过？
- 如果真实，为什么没有可验证的作品档案或授权说明？

建议二选一：

1. 有真实授权：补充作品编号、创作年份、匿名化背景、授权状态和作品图；
2. 暂无授权：统一改为“创作方向示例”“根据常见送礼情境整理”“示意性案例”，不要使用“真实故事”。

## 四、P1：直接影响获客和转化的问题

### P1-1｜首屏需要三个明确入口

建议在三组首屏画面中统一保留短文案和按钮：

- 看手写现货；
- 获取送礼建议；
- 发起定制咨询。

当前首页首屏代码只有标题、说明和轮播点，没有直接行动按钮；见 [`src/pages/index.astro:23-52`](../src/pages/index.astro)。

按钮不应使用“了解更多”这类低信息量文案，应直接告诉用户下一步会得到什么。

### P1-2｜首页应尽快呈现“两位艺术家 + 四项能力”

当前首页用户需要滚动多个区块，才能从“心意之选”理解品牌的主要业务；首页还没有将非遗小宁作为核心差异化内容呈现。

建议在首屏之后加入一行事实型说明：

> 两位艺术家，四种文化媒介：手写书法、非遗面塑、插画与空间叙事。

随后用四张能力卡：

1. 手写现货；
2. 定制手写；
3. 非遗面塑与插画；
4. 机构合作。

每张卡只回答三件事：适合谁、能得到什么、下一步点哪里。

### P1-3｜选礼指南必须从说明页变成决策页

当前 `/gift-guide/` 以说明和 FAQ 为主，普通用户缺少选择入口。

建议首屏直接提供两种选择：

```text
我想送给谁？
- 长辈
- 朋友 / 伴侣
- 老师
- 客户 / 合作伙伴
- 员工 / 团队

我为什么送？
- 生日
- 乔迁
- 开业
- 节日
- 谢师
- 周年纪念
```

选择后给出 2–3 个建议方向，并明确：

- 价格起点或询价；
- 预计时间参考；
- 是否现货 / 定制；
- 包装和贺卡是否可选；
- 直接进入咨询的按钮。

### P1-4｜详情页需要“30 秒决策摘要”

目前详情页信息量很大，包含释读、设计理念、规格、工艺、陈设、包装、FAQ 等多个章节，但普通用户首先需要的是一组简明答案。

建议在标题和长文案之间增加摘要卡：

```text
适合：谁 / 什么场合
形式：现货方向 / 定制
价格：参考起点，包含或不包含什么
时间：参考范围
得到：作品、装裱、包装、贺卡的具体组成
下一步：获取建议 / 提交定制
```

长篇文化说明放到“继续了解”之后，避免用户在还没判断是否适合时被大量文字劝退。

### P1-5｜详情页消除未经确认的具体承诺

页面出现了以下高确定性内容：

- 具体尺寸、公差、材质克重、木材含水率；
- 光学级玻璃、紫外线、耐候性等参数；
- 礼盒、证书、白手套、火漆封缄等包装配置；
- 7–10 或 10–14、14–21 个工作日等发货时间；
- 运输、承重和防变形描述。

项目 README 明确写着真实产品图片、材料、尺寸、包装、价格、运输、交期、容量、退款、联系人和授权仍需确认；见 [`README.md:29-31`](../README.md)。

建议：

- 未确认前改为“参考方向 / 具体以确认单为准”；
- 每个规格字段标注“参考”或暂时隐藏；
- 不要用精确参数制造已经可以购买的错觉；
- 真实产品资料确认后再恢复精确规格。

### P1-6｜联系页给出即时而明确的沟通方式

当前 `/contact/`：

- 邮箱可用；
- 小红书 / Instagram 写着“正式配置后更新”；
- 微信只能通过邮件留下微信号等待人工联系。

这对从小红书或熟人转介绍来的用户不够顺畅。

建议：

- 如果已有官方微信，直接展示二维码和“添加时备注：送礼 / 定制 / 企业”；
- 如果还没有可公开微信，至少把邮件主题、回复时间参考和咨询准备项写清楚；
- 社交账号未配置时不要长期保留“待更新”状态，可暂时隐藏整个社交区块。

### P1-7｜移动端底部“我的”入口命名错误

布局文件显示移动端底栏：

- “礼物”指向 `/gifts/`；
- “我的”也指向 `/gifts/`；
- “寻墨”是留言；
- “分享”是分享。

源码位置：[`src/layouts/Layout.astro:61`](../src/layouts/Layout.astro)。

如果它实际是心愿单，应改为：

- 心愿单 / Wishlist；
- 收藏 / Saved；
- 我的礼物清单。

不要使用“我的”，因为普通用户会期待登录、订单或个人中心。

### P1-8｜移动端隐藏了重要信任与联系信息

布局样式在移动端隐藏：

```css
.footer-contact,
.trust-signals,
.footer-newsletter {
  display: none;
}
```

源码位置：[`src/layouts/Layout.astro:150-155`](../src/layouts/Layout.astro)。

移动端正是小红书、微信和社交分享的主要访问来源，建议至少保留：

- 邮箱或微信二维码；
- “客户故事获授权后公开”；
- “价格 / 交付 / 售后确认后说明”；
- 一个直接咨询按钮。

## 五、P2：内容、架构和质量问题

### P2-1｜`/journal/` 路由内容错误

线上 `/journal/` 返回的是品牌介绍内容，页面标题和内容都与 `/about/` 接近，而不是创作笔记或文章列表。

建议：

- 如果 Journal 暂无内容，暂时从导航和 sitemap 隐藏；
- 如果保留，至少发布 3 类内容：
  - 一个字的来处；
  - 一件作品如何完成；
  - 面塑 / 插画 / 文化项目的创作记录；
- 每篇文章关联一件作品、一个艺术家和一个咨询入口。

### P2-2｜艺术家页存在“整理中”占位

线上两位艺术家页均出现“落地实景图整理中”“经历与展览信息将随创作笔记持续呈现”等语句。

建议：

- 未准备好就不显示空白的“经历 / 代表作品”模块；
- 用已确认事实写短简介；
- 把空缺模块改为“正在整理的创作档案”并提供明确时间或隐藏；
- 每位艺术家至少有一个清晰服务入口。

### P2-3｜灵感场景页的链接过于泛化

`/scenes/` 中书房、客厅、茶室、卧房等场景都链接到 `/gifts/`，没有链接到对应主题或作品。

建议：

- 书房 → 墨有呼吸；
- 茶室 → 墨有呼吸 / 四时一笺；
- 送礼 → 选礼指南；
- 企业伴手礼 → 企业礼赠；
- 卧房 → 一点朱砂或具体适合的纸本方向。

### P2-4｜详情页有明显文案排版瑕疵

抓取内容显示：

- “选项。。”
- “发出。。”
- 装裱形式多条内容连成一段，缺少视觉分隔。

这类细节会直接降低用户对手作品质和交付严谨度的判断。

建议统一检查：

- 重复标点；
- 中英文标题间距；
- 规格字段的标签与值排版；
- 手机端段落长度；
- FAQ 是否每题独立显示。

### P2-5｜中英文混排比例偏高

当前页面有大量 `Business Gifts / 企业礼赠`、`Chapter 01 / 释读`、`Gift FAQ / 礼物常见问题` 等双语标签。

保留英文作为品牌气质可以，但普通中文用户的核心决策信息应优先使用中文：

- 价格；
- 现货 / 定制；
- 交付；
- 包装；
- 联系方式；
- 下一步。

英文作为副标题，不应与中文信息争夺视觉层级。

## 六、当前网站值得保留的优点

1. 东方纸墨、木器、茶室和留白的视觉语言已经形成识别度。
2. 首页四类礼物方向有清晰的文学命名，可以继续发展为内容栏目。
3. 详情页愿意解释文字出处、设计理念、装裱和使用场景，这比只放商品图更有文化厚度。
4. 选礼、定制、企业礼赠和艺术家页面的业务边界已经有雏形。
5. 网站没有虚构大量客户数量、媒体背书或未经授权的 Logo，这种克制应继续保留。
6. 定制表单已有统一线索提交模块 [`src/scripts/cloud-forms.ts:14-38`](../src/scripts/cloud-forms.ts)，可以作为企业表单修复的基础。

## 七、推荐的修复顺序

### 第一轮：先修“不能转化”的问题

1. 修复 `/shop/` 404；
2. 统一“手写现货 / 私享礼遇 / 小民好礼”的命名和入口；
3. 企业表单接入真实线索接口并做提交验证；
4. 暂时移除或改写“真实故事”；
5. 修复 `/about/` 的“不卖现货”冲突。

### 第二轮：提高首次访问转化

1. 首屏加入三个行动入口；
2. 首页首屏后增加两位艺术家和四项能力；
3. 选礼指南加入场合 / 对象决策卡；
4. 详情页增加 30 秒决策摘要；
5. 联系页补充直接联系路径；
6. 移动端修正“我的”并恢复最低限度信任信息。

### 第三轮：补文化内容与 SEO

1. 修复或暂时隐藏 `/journal/`；
2. 补充艺术家真实简介和创作档案；
3. 将场景页链接到具体主题和作品；
4. 统一详情页标点、段落和中英文层级；
5. 发布可授权的作品故事和创作过程内容。

## 八、建议追踪的转化事件

当前已有自定义事件分发基础，建议形成以下事件命名：

```text
hero_ready_made_click
hero_gift_guide_click
hero_commission_click
shop_theme_view
shop_product_detail_view
gift_guide_occasion_select
gift_guide_recipient_select
consultation_start
consultation_submit_success
consultation_submit_error
business_brief_submit_success
artist_profile_view
journal_article_view
wechat_qr_click
email_click
wishlist_add
```

每个事件至少记录：

- 当前页面；
- 来源入口；
- 主题 / 场合 / 艺术家；
- 是否移动端；
- 最终是否成功提交。

不要只记录页面浏览，要能回答：

- 哪个入口带来咨询；
- 用户更常从哪类场景开始；
- 现货、定制和企业合作哪条路径流失最多；
- 表单失败是否造成线索损失。


## 十、最终判断

当前网站可以作为品牌展示型 MVP，但还不适合作为稳定的获客和转化入口。最需要优先处理的不是继续增加装饰或长文案，而是：

```text
修复入口断路
→ 统一现货与定制定位
→ 确保线索真的能收到
→ 让用户在首屏就知道下一步
→ 把未确认的事实改成明确的参考信息
```

在上述 P0 问题解决前，不建议继续投入大量首页动画、额外栏目或更多长篇产品说明。先保证普通用户能顺利完成：

```text
看懂品牌
→ 找到适合自己的方向
→ 判断价格与时间
→ 留下联系方式
→ 确认团队真的能收到
```
