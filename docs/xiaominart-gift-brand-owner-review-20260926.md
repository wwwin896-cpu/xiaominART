# 小民艺术礼品品牌化项目负责人评审意见

日期：2026-09-26  
评审人：项目负责人 / 网站开发负责人  
对照文件：`小民艺术网站结构分析报告.20260924.docx`  
项目：`xiaominart-site`

## 一、负责人结论

报告提出的最终方向是正确的：网站不应继续停留在“艺术家介绍 + 灵感展示 + 定制咨询”模式，而应逐步建设为一个以东方审美、书写温度和日常关系为核心的礼品品牌。

但当前项目的真实状态与报告中的目标状态仍有明显距离：

- 当前首页仍然以艺术定制、艺术家匹配和创作咨询为主要叙事。
- 产品和礼品数据仍主要位于 `src/data/content.ts`，没有形成完整的商品内容系统。
- Keystatic 配置已经建立，但 `content/products`、`content/scenes`、`content/blog`、`content/client-stories` 尚未成为前台的真实数据源。
- 当前站点没有真实购物车、支付、库存、订单和持久化咨询后台，这一点报告判断是正确的，不能在品牌化过程中虚构。
- 价格口径存在冲突：部分内容使用 `¥100–300 / ¥300–500 / ¥800 以上`，FAQ 和部分参考内容又出现 `¥300–¥800 / ¥800–¥2,000`。礼品品牌上线前必须统一价格表达。
- 当前主导航五项仍然偏“艺术机构/创作服务”语义，不能完全承担礼品品牌的销售和礼赠决策任务。

因此，我的建议不是推翻现有网站，而是进行一次明确的产品定位迁移：

> 保留小民艺术的文化气质和定制能力，把“礼品”提升为第一业务入口，把“艺术定制”降为高客单价、企业礼赠和特殊场景的升级服务。

## 二、最终品牌定位建议

### 2.1 建议的品牌核心

品牌名称继续使用：

> **小民艺术｜日常之礼**

建议对外的品牌定义为：

> **有东方审美和人情温度的当代礼品品牌。**

英文辅助表达可以保持：

> **XIAOMINART — Thoughtful gifts for everyday rituals.**

这里的关键不是把品牌做成传统工艺店，也不是把所有商品都包装成艺术品，而是建立一个清晰的礼品判断标准：

1. 送礼对象明确。
2. 使用场景明确。
3. 预算区间明确。
4. 礼物有可解释的寓意和故事。
5. 包装、贺卡、交付时间说清楚。
6. 必要时可以升级为手写、定制或企业礼赠方案。

### 2.2 品牌应该卖什么

第一阶段不建议把品类扩张得过大。建议围绕三个核心资产建立商品线：

- **书写**：亲笔书法、手写祝福、文字和纸本礼品。
- **器物**：茶、案头、居家和日常使用相关的东方器物。
- **礼盒**：针对生日、乔迁、节日、感谢、开业、企业礼赠的组合方案。

产品不只是“一个物件”，而是：

> 物件 + 寓意 + 包装 + 贺卡 + 场景建议 + 交付说明。

这会让小民艺术与普通礼品电商产生区隔，也能保留品牌的文化表达。

## 三、网站应该从“展示型艺术站”转成“礼赠决策站”

### 3.1 当前网站的问题

目前的首页结构具有审美和内容基础，但用户进入后首先看到的是：

- 艺术定制流程。
- 艺术家匹配。
- 生活场景灵感。
- 艺术礼盒概念。
- 定制咨询。

这套结构更像“艺术创作工作室或定制平台”，用户仍需要自己理解：

- 我现在应该买什么？
- 送给谁合适？
- 多少钱？
- 什么时候能收到？
- 是否包含包装和贺卡？
- 如果我不懂艺术，如何选择？

礼品品牌必须把这些问题提前回答。

### 3.2 建议的首页叙事顺序

首页第一屏建议从“礼赠任务”而不是“艺术创作流程”开始：

1. 品牌承诺：有文化温度的东方日常之礼。
2. 立即入口：按送给谁、什么场合、预算选择礼物。
3. 三个礼品层级：入门表达、认真心意、珍藏礼赠。
4. 真实礼赠场景：生日、乔迁、节日、感谢、开业、企业。
5. 产品/礼盒推荐。
6. 包装、手写贺卡和交付说明。
7. 为什么选择小民艺术。
8. 定制升级入口。
9. Journal / 品牌故事 / 创作过程。

当前“四步共创”可以保留，但应下移到“定制升级”区域，不应压过商品礼赠入口。

## 四、建议的最终网站结构

### 4.1 顶部主导航建议

如果品牌最终目标确实是礼品品牌，我建议将主导航从“艺术分类”改为“用户任务分类”。建议第一版采用：

1. **礼品** → `/gift-guide/` 或 `/gifts/`
2. **按场合选礼** → `/occasions/`
3. **按对象选礼** → `/recipients/`
4. **企业礼赠** → `/business-gifts/`
5. **品牌故事** → `/about/`

“手写书法、手作/插画、非遗/器物”不必删除，可以放入：

- 礼品页筛选项。
- 二级菜单。
- 品类页。
- 页脚入口。
- Journal 内容分类。

如果当前阶段必须保留已经确认的五项主导航，则建议至少把第一项“手写书法”改成“礼品 / Gift Guide”，并把艺术分类放入二级菜单。否则网站的第一印象仍然是艺术网站，而不是礼品品牌。

### 4.2 必须建立的页面

#### 礼品决策页

- `/gift-guide/`：按预算、对象、场合、风格筛选。
- `/gift-guide/[slug]/`：单个礼品或礼盒详情。
- `/occasions/`：生日、乔迁、节日、感谢、开业、周年。
- `/recipients/`：送长辈、伴侣、朋友、老师、客户、领导、员工。
- `/collections/`：季节、节气、主题和限量系列。

#### 品牌与内容页

- `/about/`：品牌故事、审美标准、艺术家与供应/创作边界。
- `/journal/`：礼物文化、书写、器物、场景和创作笔记。
- `/stories/`：经过授权的客户故事和礼赠案例。
- `/faq/`：价格、包装、交付、定制、版权和售后说明。

#### 服务页

- `/business-gifts/`：企业礼赠、数量、预算、交付周期和咨询入口。
- `/custom-commission/`：高客单价定制，不作为普通礼品购买的默认入口。
- `/contact/`：联系与邮件入口。

## 五、产品系统必须从“艺术作品”升级为“礼品商品”

当前 `keystatic.config.ts` 中的产品字段已经是基础，但还不足以支撑礼品品牌运营。产品内容模型建议增加以下字段：

### 5.1 商品基本信息

- 商品标题。
- 英文标题。
- slug。
- 商品类型：单品、礼盒、定制礼、企业礼赠。
- 品类：书写、器物、插画、礼盒、空间礼赠。
- 发布状态。
- 首页推荐。
- 上新状态。
- 季节/节气标签。

### 5.2 礼赠决策字段

- 适合送给谁。
- 适合什么场合。
- 礼物寓意。
- 推荐预算。
- 风格关键词。
- 适合的空间或使用场景。
- 关系距离：日常、熟人、重要关系、商务关系。
- 选择理由。

### 5.3 交付与服务字段

- 价格区间。
- 是否支持手写贺卡。
- 是否支持礼盒包装。
- 包装说明。
- 预计制作/发货时间。
- 是否支持加急咨询。
- 是否支持批量企业礼赠。
- 物流说明。
- 售后和退换边界。

### 5.4 素材字段

- 主图。
- 细节图。
- 包装图。
- 场景图。
- 文字 alt。
- 图片授权状态。
- 图片来源和内部备注。

### 5.5 CTA 字段

每件产品不应该只有“咨询”一个按钮，建议根据状态显示：

- 立即了解。
- 查看适合对象。
- 加入礼物清单。
- 获取送礼建议。
- 发起定制咨询。
- 企业批量咨询。

当前没有真实购物车、库存和支付时，可以先使用“获取送礼建议 / 邮件咨询”作为诚实的转化入口，不要伪装成可直接下单的电商系统。

## 六、Keystatic 应该成为运营后台，而不是只做内容展示

### 6.1 现有配置的优点

当前 Keystatic 已经具备：

- 网站设置单例。
- 导航单例。
- 产品集合。
- 场景集合。
- Journal 集合。
- 客户故事集合。
- GitHub 存储模式。
- Vercel SSR 生产构建条件。

这说明基础方向没有问题。

### 6.2 当前必须补齐的部分

#### 内容读取层

报告要求创建 `src/lib/keystatic.ts`，但当前页面仍大量直接读取 `src/data/content.ts`。下一阶段必须建立统一读取层：

- 前台优先读取 `content/` 内容。
- 未迁移内容可以暂时回退到 `src/data/content.ts`。
- 迁移完成后逐步删除重复数据源。
- 页面不要同时维护两套产品标题、价格和文案。

#### 导航二级关系

当前 `menuItem` 只有 label、英文、链接、显示和排序，没有 `children[]`。报告要求支持二级菜单关系，这项必须真正加入模型，而不是只在文档里声明。

建议：

- `children[]` 使用递归或固定深度对象。
- 桌面端支持 hover/focus 下拉。
- 移动端支持点击展开。
- 每个子菜单项同样有 visible、order、href。
- 菜单隐藏不等于删除内容。

#### Logo 管理边界

正式 SVG Logo 是品牌资产，不建议让后台直接改 SVG 文件内容。Keystatic 只管理：

- Logo 副标。
- alt 文本。
- SEO 标题。
- Logo 使用版本说明。

Logo 文件本身由代码仓库控制，防止运营误改品牌资产。

#### 咨询数据边界

报告不建议使用 Vercel 临时文件写入，这是正确的。企业咨询和普通礼品咨询应区分：

- 普通咨询：可靠表单服务或邮件通知。
- 企业咨询：表单服务、CRM 或受控 API。
- Keystatic：管理页面说明、FAQ 和运营内容，不直接充当高频咨询数据库。

## 七、价格和商品承诺必须先统一

当前存在两个价格体系：

### 报告锁定的礼品档位

- `¥100–300`
- `¥300–500`
- `¥800 以上`

### 当前内容中出现的其他参考

- `¥300–¥800`
- `¥800–¥2,000`
- 商业空间项目单独评估。

我的建议是分成两套明确语义：

#### 普通礼品导航档位

- 入门表达：`¥100–300`
- 认真心意：`¥300–500`
- 珍藏礼赠：`¥800 以上`

#### 定制/空间项目参考

- 中型墙面或器物定制：`¥300–¥800`
- 高复杂度器物或作品：`¥800–¥2,000`
- 商业空间和大型项目：单独评估。

这两套不能在同一个礼品筛选器中混用，否则用户会误解价格。需要在内容模型和 FAQ 中明确区分“礼品价格档位”和“定制项目参考”。

## 八、品牌内容方向建议

### 8.1 Journal 不应只写艺术创作

建议建立四个长期内容栏目：

1. **送礼方法**：如何为不同关系和场合选礼。
2. **东方日常**：书写、茶、器物、空间和生活方式。
3. **礼物故事**：真实授权后的客户和企业礼赠故事。
4. **创作手记**：艺术家、材料、工艺和定制过程。

这样 Journal 才能同时承担 SEO、品牌教育和转化作用。

### 8.2 产品文案结构

每个礼品详情页建议固定回答：

1. 这是什么。
2. 适合送给谁。
3. 适合什么场合。
4. 它表达什么心意。
5. 为什么是这个价格区间。
6. 包装和贺卡包含什么。
7. 什么时候能收到。
8. 如果不确定，下一步怎么咨询。

## 九、视觉与交互方向

现有视觉基调可以保留：纸色背景、朱砂、金石印章、书写与安静留白。这是品牌差异化资产。

但礼品品牌需要增加三个明确的视觉语言：

- **礼物识别**：礼盒、包装、贺卡和开箱场景不能只作为文字说明，应有真实图片或明确占位。
- **选择效率**：预算、对象、场合筛选要比艺术家介绍更显眼。
- **信任感**：交付时间、包装标准、咨询响应和授权状态要清楚。

建议保持“高级沉静”，避免变成：

- 过于文艺但无法选择。
- 只有概念图没有商品信息。
- 只有大段品牌文案没有购买/咨询路径。
- 过度电商化、优惠券化和低价促销化。

## 十、项目执行优先级

### P0：先完成礼品品牌骨架

1. 最终确定主导航是否从艺术分类改为礼赠任务分类。
2. 统一普通礼品档位和定制项目价格口径。
3. 建立 `src/lib/keystatic.ts` 内容读取层。
4. 建立至少 6–10 个真实或已确认的礼品内容条目。
5. 完善产品字段：对象、场合、寓意、包装、贺卡、交付、咨询。
6. 实现礼品筛选入口：预算 + 对象 + 场合。
7. 首页第一屏和第一组 CTA 以礼品为中心。
8. 保留艺术定制作为升级服务。

### P1：完成前台数据化和礼品体验

1. 礼品列表和详情页读取 Keystatic 内容。
2. 场合页和对象页建立内容结构。
3. 礼物清单/收藏功能与产品数据打通。
4. 产品图片、包装图片和场景图片补齐。
5. FAQ、交付和售后说明集中维护。
6. Journal 建立四个内容栏目。
7. 移动端筛选和导航体验验收。

### P2：再做商业化能力

1. 可靠咨询表单和邮件通知。
2. 企业礼赠批量询价。
3. 产品库存或供应状态接入。
4. 支付和订单系统评估。
5. CRM、复购、会员或私域沉淀。
6. 数据分析：礼品筛选、详情阅读、咨询提交和转化路径。

## 十一、我作为负责人给出的最终判断

### 应该坚持的

- “小民艺术｜日常之礼”品牌方向。
- 东方审美、书写、器物和人情关系的内容资产。
- 纸色、朱砂、金石、留白的视觉语言。
- 礼品与艺术定制之间的升级关系。
- 内容真实、授权优先、不虚构交易能力。
- Keystatic + GitHub + Vercel 作为内容发布链路。

### 应该调整的

- 首页不要继续以艺术家和定制流程作为第一主叙事。
- 顶部导航要优先服务礼品选择任务。
- 产品内容必须从 TypeScript 硬编码迁移为 CMS 真数据源。
- 产品字段必须补齐礼赠决策、包装和交付信息。
- 普通礼品价格与定制项目价格必须分开。
- “艺术礼盒”不能只有概念文案，需要真实可管理的礼品条目。
- Keystatic 后台不能只做到“能打开”，还要做到运营人员能维护一件礼品的完整信息。

### 最终目标

网站最终不是一个“介绍小民艺术是谁”的网站，而是一个能让用户完成以下动作的礼品品牌平台：

> 我想送一份有文化温度的礼物 → 我说清楚对象、场合和预算 → 网站给我合理的方向 → 我看懂礼物的寓意、包装和交付 → 我可以直接了解、收藏或发起咨询 → 重要礼赠再升级为定制服务。

这条链路建立起来后，小民艺术才真正从“艺术内容网站”进入“礼品品牌网站”。
