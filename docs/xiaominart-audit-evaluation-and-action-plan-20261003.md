## 一、总体评估

这份审计质量很高，**可以作为修复依据**。10 项高优问题中 9 项经独立复验属实；"转化链路没有闭合"的核心判断准确；先修断路、再做转化的三批顺序合理。

我的补充集中在三处：**2 个新发现**（审计未覆盖，其中一个比审计的对应判断更严重）、**2 个降级修正**（审计高估了两个问题）、**1 个落地前置条件**（审计的修复方案按原文执行会失败）。

## 三、我的新发现与修正

### 1.（新发现，高优先级）移动端"页脚微信"死循环

证据链：

- 联系页引导用户："**急事建议直接加页脚微信**"；
- 页脚确实有微信二维码（`Layout.astro:122` `.wechat-qr`）；
- 但移动端 CSS（`Layout.astro:152`）把 `.footer-contact` 整个 `display:none`。

结论：**移动端用户被指引去找一个被 CSS 隐藏的入口**。移动端恰恰是小红书/微信引流的主要来源，这是当前最隐蔽的一处线索流失。修复成本一行 CSS + 一段简化布局，应排进第一批。

### 2.（修正）`/journal/` 不是路由错误，问题被高估

审计 P2-1 认为是"内容架构和 SEO 入口失配"。实际是 `_redirects` 中的刻意迁移规则（旧 blog/Journal 整体 301 到 about），且 grep 确认站内源码**零引用** `/journal/`。除历史外链外几乎没有流量进入。**建议：无需处理，从 P2 清单移除**；若未来真要开 Journal，再新建页面并改这条重定向。

### 3.（修正）`/shop/` 404 的真实性质：定位缺席，不只是断链

`/shop/` 无页面、无重定向，但 grep 确认**站内也没有任何入口指向它**——审计所说"用户从现货/购物入口遇到断路"的前提并不成立。真正的用户困惑在定位层：站内没有一个叫"现货"的地方，导航叫"私享礼遇"，首页叫"心意之选"，详情页叫"小民好礼"，about 又说"不卖现货"。

**因此 `/shop/` 不需要新建页面**，走 `_redirects` 加一条 301 即可（项目已有成熟的 301 去重实践，如 `/inspiration → /gifts/`）。核心工作是把命名统一这件事做完（见四-6）。

### 4.（前置条件）企业表单修复方案需要两处改动，不是一处

审计建议"复用 `submitLead('business_gift', ...)`"。但 `functions/api/lead.ts:17` 的白名单：

```ts
const ALLOWED_FORM_TYPES = new Set(['quick_message', 'commission']);
```

**不含 `business_gift`**，前端直接调用会被 400 拒绝（"未知表单类型"）。修复必须同步两处：

1. 服务端白名单加入 `'business_gift'`；
2. `business-gifts/index.astro` 脚本改调 `submitLead`，处理成功/失败/网络异常三态，替换"本机草稿"提示文案。

除这两处外，基础设施（同源代理、WorkBuddy 云数据库、蜜罐反垃圾 `isHoneypotFilled`）全部现成，**总工作量约半小时**，是全清单性价比最高的修复。

## 五、转化事件：先做最小集

审计第八节的 16 个事件命名合理，但建议第一版只接 **6 个核心漏斗事件**，两周后看数据再扩展：

```text
hero_cta_click          { slot: ready_made | guide | commission }
gift_guide_select       { type: recipient | occasion, value }
consultation_start      { source_page }
consultation_submit     { status: success | error }
business_brief_submit   { status: success | error }
contact_channel_click   { channel: wechat | email }
```

技术上不引入第三方统计：加一个 `/api/event` Pages Function（复用 `lead.ts` 的同源代理模式）写入云数据库即可，与现有链路一致、无 Cookie 合规负担。核心要能回答三个问题：**哪个入口带来咨询、哪条路径流失最多、表单失败有没有吃掉线索**。

## 六、需业主确认后才能动的事实清单

以下内容代码层面只能改措辞，最终事实须业主拍板（承接审计 P1-5 与 README 待确认项）：

1. 现货的真实状态：四个主题各有多少、是否可即时购买；
2. "心意起点 ¥300/¥800" 的包含范围（作品/装裱/包装/贺卡/配送）；
3. 详情页全部精确规格：尺寸、材质克重、木材含水率、交期；
4. 包装配置：礼盒、证书、白手套、火漆是否为标准配置；
5. 官方微信是否可公开、小红书/Instagram 账号；
6. 首页四个故事的授权状态（决定是补证据还是维持"示例"标签）；
7. 企业起订量（50/100/200）与预算档位是否为正式报价结构。

## 七、结论

审计的方向判断我完全认同：**当前是合格的品牌展示 MVP，不是稳定的获客入口**。在我复核后，修复优先级建议调整为：

```text
1. 企业表单接真实线索（含服务端白名单，约半小时，止损最大）
2. 移动端恢复页脚联系区（一行 CSS，修复"页脚微信"死循环）
3. /shop/ 301 + 首页故事标签改写（十分钟级，堵住信任漏洞）
4. 首屏三入口 CTA（半天，转化核心）
5. 统一"现货"命名与 about 定位（需业主确认事实后执行）
6. 选礼决策卡 + 详情页摘要（第三批，把说明页变决策工具）
```

前 3 项合计不到一天工作量，完成后网站的线索链路即从"事实性丢失"转为"可追踪可验证"，这是整个修复计划里收益最集中的部分。
