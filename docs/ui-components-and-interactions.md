# XiaominART UI 组件库与交互文档

**版本**：v1.1  
**适用项目**：`xiaominart-site/`（Astro + Sanity 占位 + Vercel）  
**品牌定位**：东方艺术定制平台，不卖现货装饰画。  
**核心转化**：从具体的人、空间、关系或意图开始，进入定制沟通；不是购物、下单或库存浏览。

> 本文是当前 Demo 的 UI 与交互契约。独立组件以 `src/components/` 中的 Astro 组件为实现参考；`Button`、`Hero`、`ProcessStep` 与 `Footer` 当前分别由全局样式、首页结构或 `Layout.astro` 实现，后续可在不改变契约的前提下组件化。

## 1. 设计基线

### 1.1 视觉原则

- **高级但不疏离**：用编辑式留白、纸张层次与清晰信息结构表达品质，不使用高冷大师殿堂或奢侈品展厅语言。
- **沉静但不空泛**：每个模块只承担一个主要阅读或行动任务，文案必须说明创作方向、参考性质或下一步。
- **东方但不复古堆叠**：东方艺术通过书写、材料、留白、关系和日常场景呈现，不使用大面积祥云、复杂边框或仿古印刷装饰。
- **案例即参考**：案例、艺术家视觉和礼盒方向均为灵感入口，不能呈现为现货商品、同款商品或库存目录。
- **直角与细线**：卡片和输入框保持直角，使用低对比细边框建立秩序，避免卡片阴影堆叠。

|---|---|---|
| Display | `clamp(54px, 7.8vw, 98px)` | 首页主张；短句优先，移动端允许自然换行 |
| H1 | `36–64px` | 页面主标题，中文使用人文衬线 |

| 正文 | `16px / 1.8` | 中文长文保持舒适阅读宽度 |

### 1.4 空间与容器

- 内容最大宽度：`1200px`（`--container`）。
- 桌面安全边距：`clamp(24px, 5vw, 80px)`；源码通用容器在移动端收窄为左右 `16px`。
- 正文阅读宽度：`680–760px`；说明性段落不超过约 `600px`。
- 桌面区块垂直间距：`96px`（`--space-24`）；移动端区块垂直间距约 `64px`。
- 直角：`--radius: 0`；不以阴影代替边界。
- 视觉分组优先使用留白和细线，而不是背景色堆叠。

## 3. 全局状态、行动与业务边界

### 3.1 Button 语义

`.btn-primary` 是主要行动，`.btn-secondary` 是次级行动，`.btn-link` 是轻量文本链接。所有按钮必须说明下一步，不得使用“购买”“立即下单”“加入购物车”“Checkout”等词。

| 类型 | 视觉 | 允许文案示例 | 允许目标 |
|---|---|---|---|
| Primary | 朱砂底、纸白字、直角 | `开始定制创作 / Custom Commission` | `/custom-commission/` |
| Secondary | 透明底、墨色边框 | `浏览灵感参考 / Explore inspiration` | `/inspiration/` 或同页锚点 |
| Link | 朱砂文字 + 下边线 | `以此为灵感定制 / Commission from this direction →` | `/custom-commission/` |
| B2B primary | 深色区内朱砂底 | `提交项目简报 / Share a brief →` | `/business-custom/` |
| Disabled | 正常布局、降低不透明度 | `联系方式待确认 / Contact details to be confirmed` | 不应产生错误跳转 |

### 3.2 通用状态

- **默认态**：纸白背景、墨色文字、低对比边界。
- **hover**：只改变颜色、下划线或向上 `1px`；不放大、不弹跳。
- **首屏边界**：必须直接说明“不售卖现成画作，仅接受艺术定制共创”，主 CTA 使用“开启定制咨询 / Begin a consultation”。
- **focus-visible**：使用 `--focus`（深朱砂 `2px` 轮廓），不依赖 hover。
- **active/selected**：使用文字、边线或朱砂标记表达，不只改变颜色。
- **disabled**：`opacity: .5`、禁止交互，并在邻近文案说明未开放原因；不能伪装成成功。
- **loading/pending**：保留原文案或附加“处理中 / Sending…”；不显示“已提交”直到真实服务确认。
- **error**：在原位置提供原因与下一步；不清空用户已填写内容。
- **empty**：说明内容为何为空、何时可能补齐或如何进入定制，不调用图库填充。

### 3.3 禁止的商业交互

全站不得新增或恢复：购物车、checkout、商品价格、库存数字、现货标签、购买按钮、订单确认、支付成功、自动履约承诺。案例、艺术家、艺术礼盒和 B2B 入口均只能引导定制沟通。

## 4. 组件规范

### 4.1 SiteHeader

**实现**：`src/layouts/Layout.astro`。导航顺序必须固定为：

1. 定制创作｜Custom Commission
2. 艺术家｜Artists
3. 灵感参考库｜Inspiration Gallery
4. 艺术礼盒｜Art Gift
5. 品牌介绍｜About
6. B端企业定制｜Business Custom

**默认态**：

- sticky 顶部，纸白半透明背景，底部 `1px` 线；
- 左侧显示 `XiaominART` 与 `东方艺术定制平台 / Art, made personal`；
- 导航项为中英文两行，墨色文字；
- 桌面右侧为“开始定制”文本 CTA，不出现购买行动。

**桌面交互**：

- 当前页面通过路由或朱砂短线清晰表达；
- hover 仅切换朱砂色或短线，不改变布局高度；
- 触发焦点后可用 Enter 激活，Tab 顺序为品牌 → 导航 → CTA；
- sticky 不覆盖跳转目标，页面区块需预留锚点滚动空间。

**移动端交互**：

- `767px` 以下显示 `菜单 / Menu` 按钮，最小触控高度 `44px`；
- 按钮同步 `aria-expanded` 和 `aria-controls="site-nav"`；
- 打开后导航垂直展开，页面滚动锁定；
- 点击任意导航项后关闭菜单；按 `Escape` 关闭；
- 关闭后焦点应回到菜单按钮；后续组件化时必须保持该行为。

**异常/禁用**：

- 联系方式未确认时显示“联系方式待确认”，不显示虚构电话或地址；
- 路由未发布时不渲染死链；
- 不能用菜单折叠隐藏业务边界或案例提示。

### 4.2 Button

**实现**：全局 `.btn`、`.btn-primary`、`.btn-secondary`、`.btn-link`。

**尺寸与状态**：

- 主按钮最小高度 `48px`，左右内边距约 `22px`；
- 文本链接保持最小可读点击区域，必要时通过外围 padding 达到 `44px`；
- `hover` 向上 `1px`，颜色过渡约 `250ms`；
- `:focus-visible` 显示深朱砂轮廓；
- `disabled` 禁止 pointer 行为并提供原因；
- 提交中不得改成“订单处理中”，只能使用“正在发送 / Sending…”等意向沟通语义。

**文案边界**：

- 允许：开始定制、提交定制意向、浏览灵感、查看艺术家、阅读 Blog、提交项目简报；
- 禁止：购买、立即下单、加入购物车、确认订单、支付、库存、现货。

### 4.3 Hero

**实现**：首页 `src/pages/index.astro` 的 `.hero` 区域。

**内容结构**：

- 眉题：东方艺术定制平台；
- 中文主标题：与你创作独一无二的作品；
- 英文解释：Co-create one-of-a-kind artwork with you；
- 中文说明：从关系、空间或想留下的话开始；
- Primary：开始定制创作 / Custom Commission；
- Secondary：浏览灵感参考 / Explore inspiration；
- 右侧视觉说明每个案例是创作方向记录，不是现货陈列。

**构图**：桌面采用左文案右视觉的非对称分栏；移动端改为文案在上、视觉在下。概念视觉或抽象方向图旁必须明确“概念方向 / Conceptual direction”，不能让占位图看起来像可购买商品。

**交互**：

- CTA hover 只改变朱砂深浅或下划线；
- 视觉不做自动轮播、不做持续视差、不自动播放视频；
- 若未来接入真实作品图，必须同步 alt、授权状态和非量产/交付状态；
- 无真实图时保留有意设计的抽象占位，不使用随机图库。

### 4.4 ProcessStep

**实现**：首页 `.process-step`；数据来自 `src/data/content.ts` 的 `processSteps`。

四个步骤固定为：

1. 说出愿望 / Share the intention
2. 共同取意 / Shape the direction
3. 艺术家创作 / Artist at work
4. 交付一份作品 / Receive the work

**视觉**：四列由细线分隔，步骤编号朱砂，标题使用中文衬线，英文副题使用英文衬线，说明保持柔墨色。移动端改为单列并以水平细线分隔。

**交互**：步骤默认是阅读内容，不设计为可点击 tab，不模拟进度完成。未开放步骤要使用“准备中 / In preparation”说明，不出现虚构时限。

### 4.5 InspirationCard

**实现**：`src/components/InspirationCard.astro`。

**内容**：方向名、英文名、类别、简短说明、抽象视觉或授权图、案例固定提示、进入详情和定制 CTA。

**必须显示的固定文案**：

> 案例仅作风格参考，不售卖同款 | For reference only, identical artwork is not for sale.

不得只在详情页或页脚显示；灵感库列表、首页灵感卡、详情页和社交分享落地页都应保留这条边界说明。

**交互**：

- 图像 hover 只轻微改变亮度或标题下划线；
- 整张视觉区域可进入方向详情，但卡片 CTA 必须直接指向 `/custom-commission/`；
- 无图使用纸色/豆青抽象占位，不引入未授权摄影；
- 错误加载显示“图像暂不可用 / Image unavailable”，同时保留案例提示和定制 CTA。

### 4.6 ArtistCard

**实现**：`src/components/ArtistCard.astro`。

**内容**：艺术家/方向名称、英文名、创作媒介或方向、简短简介、查看详情。

**视觉**：左侧抽象标记或经授权的肖像/作品图，右侧文字；桌面两栏，移动端缩为窄图 + 文字。

**交互与边界**：

- `查看艺术家 / View artist` 进入详情页；
- 详情页 CTA 使用“邀请参与定制 / Invite this artist”，进入表单或带方向参数的表单；
- 不显示虚构履历、成交数量、作品价格、库存或可直接购买的作品；
- 资料缺失时显示方向说明或“资料待确认”，不以假数据补齐。

### 4.7 B2BPanel

**实现**：`src/components/B2BPanel.astro`，首页另有同一语义的深色 B2B 区。

**视觉**：墨色底、纸白文字、朱砂 CTA、鎏金 `B2B` 或编号；避免企业软件 dashboard 感。

**内容**：企业礼赠、文化空间、婚礼与周年、品牌活动等项目方向；先提交场景，再讨论艺术家、媒介、尺度和边界。

**交互**：

- 主 CTA 为 `提交项目简报 / Share a brief`，目标 `/business-custom/`；
- 不显示客户 Logo、案例数量、项目金额、交期或产能，除非 Sanity 中已有事实来源；
- 无案例时显示服务范围空状态，不显示“暂无客户”这类削弱品牌的占位语；
- 深色区中焦点轮廓仍需可见，使用纸白/深朱砂对比。

### 4.8 FormField

**实现**：`src/components/FormField.astro`；当前使用原生 `input` 与 `textarea`。

**字段顺序**：称呼 → 场景 → 意图 → 艺术方向 → 隐私选择。B2B 表单可增加项目类型、预计范围和目的地，但不引入价格或订单字段作为承诺。

**字段规则**：

- 必填：称呼、场景、意图；
- label 必须可见，`name` 稳定，必填使用文字和 `required` 属性；
- placeholder 是提示，不替代 label；
- 输入框纸白底、直角、`1px` 线，默认行高继承正文；
- 长文本允许垂直调整大小，不允许横向拖拽。

**状态与提交**：

- 默认私密选项预选；公开案例不是提交前置条件；
- 浏览器校验失败时不清空内容，焦点回到第一个错误字段；
- 错误文字紧邻字段，说明具体缺什么；不能只用红色；
- 当前 Demo 使用 `mailto` 回退，必须显示“提交后仅用于初步沟通，不代表项目确认”；
- 真实表单服务接入后，提交成功只能显示“已收到定制意向 / Brief received”，不能显示支付或订单状态；
- 发送失败保留全部输入并给出重新发送或其他联系方式，联系方式未确认时标记待确认。

### 4.9 CaseNotice

**实现**：`src/components/CaseNotice.astro`。

**固定内容**：

`案例仅作风格参考，不售卖同款 | For reference only, identical artwork is not for sale.`

**视觉**：朱砂深色小字号，靠近案例图或案例标题；不是隐藏在 hover、tooltip 或折叠面板中。紧凑模式可使用 `11px`，但不得低于可读范围。

**状态**：

- 默认与 compact 均始终显示；
- 不闪烁、不自动消失、不因移动端空间不足而删除；
- 若案例授权撤回，显示“资料待确认 / Details to be confirmed”，并隐藏不应公开的媒体，同时保留清晰边界；
- 不允许替换成“仅供参考”而删掉“不售卖同款”的事实边界。

### 4.10 BlogCard

**实现**：`src/components/BlogCard.astro`。

**内容**：内容支柱、中文标题、英文副题、摘要、阅读时间/元数据、阅读链接。

## 7. 动效与性能边界

### 7.1 允许的动效

- 首屏文案/视觉错时淡入：`400–700ms`；
- 卡片 hover 轻微亮度、颜色或下划线变化；
- CTA hover 向上 `1px`；
- 锚点切换使用平滑滚动（非 reduced motion）；
- 菜单打开/关闭使用短暂淡化或高度展开，不使用弹跳。

### 7.2 禁止的动效

- 自动轮播、持续视差、闪烁、粒子、金色流光；
- 大幅缩放或旋转书法/艺术图；
- 自动播放有声视频；
- 为制造“高级感”而加入遮挡正文的过场动画；
- 任何会改变案例提示、隐私说明或业务边界可见性的动画。

### 7.3 Reduced motion

`@media (prefers-reduced-motion: reduce)` 下：

- `scroll-behavior` 改为 `auto`；
- transition/animation 时长降为近乎即时；
- 关闭位移、淡入、视差和自动滚动；
- 菜单、表单、展开内容仍必须可用。

### 7.4 性能

- 首屏图像使用真实媒体与合适尺寸，概念占位不加载随机远程资源；
- 视频只在用户主动播放时加载或播放；
- Sanity 图像必须维护 alt、授权状态和内容状态；
- 懒加载不能延迟关键 CTA、概念边界、隐私说明或错误提示；
- 错误媒体要回退到语义明确的占位状态。

## 8. 无障碍要求

- 页面提供 skip link，主内容从 `#main` 开始；
- 所有导航、按钮、折叠和表单控件可用键盘操作；
- 触控目标至少 `44px`；
- `aria-expanded`、`aria-controls`、label/for 或等效可访问名称必须同步；
- 焦点轮廓使用深朱砂并保持足够对比度；
- 颜色不是唯一状态提示：错误、待确认、概念和激活态都要有文字或结构信息；
- 图片 alt 描述“内容 + 场景”，不写“图片 1”；装饰性抽象占位可使用空 alt；
- 中英文切换使用正确 `lang` 标记；
- 长标题、案例提示和表单错误在 `375px` 宽度下不得被截断；
- 动效遵守 reduced-motion 设置；
- 表单错误需可被读屏器关联到字段，后续接入服务时补充 `aria-live` 状态区。

## 9. 空、错误、禁用状态文案

| 场景 | 中文 | English | 处理 |
|---|---|---|---|
| 内容为空 | 内容准备中 | Content in preparation | 保留页面结构，说明真实资料确认后公开 |
| 概念视觉 | 概念方向 | Conceptual direction | 靠近图像显示，不表示量产 |
