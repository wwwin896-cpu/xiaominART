## 三、本次发现并修复的真实缺陷

### 缺陷 1（高隐蔽）：5 个埋点事件被静默丢弃

P0-03 / P1-02 / P0-04 三个工单的组件里都写了

```js
window.dispatchEvent(new CustomEvent('xiaominart:event', { detail: { name: 'search_open', ... } }));
```

但**两端白名单都没登记**，事件在 `trackEvent()` 第一行就被丢弃：

```ts
export function trackEvent(name, data = {}) {
  if (!TRACKED_EVENTS.has(name)) return;   // ← 这里 return，请求根本不发
```

**无任何报错、无控制台输出、无网络请求** —— 除非拿白名单做差集，否则永远发现不了。

丢失的 5 个事件：

| 事件 | 来源工单 | 业务含义 |
|---|---|---|
| `search_open` | P0-03 | 搜索浮层打开率 |
| `search_result_click` | P0-03 | 搜索带来的实际跳转 |
| `wishlist_drawer_open` | P1-02 | 收藏清单查看率 |
| `wechat_direct_open` | P0-04 | 绕过表单的即时沟通意图 |
| `wechat_id_copy` | P0-04 | 最接近「即将加好友」的动作 |

### 缺陷 2（结构性）：`[data-event]` 监听对动态节点完全失效

`Layout.astro` 原写法：

```js
document.querySelectorAll('[data-event]').forEach((el) => el.addEventListener('click', ...));
```

这是**加载时一次性绑定**，因此组件**动态插入**的节点永远收不到监听：

- 搜索结果项（`SearchModal` 运行时 `createElement('a')`）
- 选礼器选项卡、心愿单抽屉条目

**这正是 `search_result_click` 从未上报的根因** —— 即使补了白名单，只要监听方式不改，
动态节点上的 `data-event` 就是死代码。

**修法**：改为 document 级事件委托

```js
document.addEventListener('click', (event) => {
  const el = event.target?.closest('[data-event]');
  if (!el) return;
  ...dispatch...
});
```

一处修复同时救活「搜索结果项」「选礼器选项卡」等**所有**未来新增的动态埋点节点。

### 修复清单
