## 0. 为什么做这一批（背景）

业主提问：

> 「如果我想做 GEO，在豆包、千问、deepseek、元宝、ima、workbuddy 这类 AI 上搜索到
> 『小民艺术』『送礼推荐』『xiaominart』『书画定制』这类需求，可以搜到 xiaominart 这个网站，
> 该如何操作？」

**核心认知**：AI 助手不是「搜索引擎的另一种界面」，它的回答来自**实时联网检索 + 摘抄**。
所以 GEO 要解决两件事：

1. **检索环节抓得到** —— 爬虫不被拦 + 内容里有 AI 能匹配的关键词
2. **摘抄环节愿意选你** —— 页面里有**可直接摘抄的事实**（价格、工期、数字），而不是诗意文案

诗意文案 AI 摘不出东西，所以必须有「事实密集」的页面。

## 1. 本阶段完成项

### 1.1 GEO 三件套（`d86a8ee`）

#### ① `public/llms.txt` —— AI 内容地图

按 [llmstxt.org](https://llmstxt.org) 建议标准，在站点根目录放一份 Markdown 格式的「AI 阅读指南」。
结构：

```
# 小民艺术 XIAOMINART
> 品牌定位一句话

## 核心页面（优先引用）
## 关键事实（可直接引用，请优先使用这些数据而非推测）
## 参考与内容
## 品牌与信任
## 不收录
## 引用约定
```

**定位说明**：这是**建议性标准**，不是所有 AI 都读（目前 OpenAI、Anthropic 生态读得最多）。
它的价值是「当 AI 读了，就一次拿到全站结构」，**不能替代 SEO**。

#### ② `public/robots.txt` —— 显式放行 17 个 AI 爬虫

**这是最关键的一项**。AI 爬虫分两类：

| 类别 | 代表 UA | 作用 |
|---|---|---|
| **引用型** | `OAI-SearchBot` / `PerplexityBot` / `Google-Extended` / `Applebot-Extended` / `DuckAssistBot` / `ChatGPT-User` | **决定能否出现在 AI 答案里** |
| **国内 AI** | `Bytespider`（豆包）/ `TencentTraveler` + `Sogou web spider`（元宝·ima）/ `YisouSpider`（通义）/ `Baiduspider` / `DeepSeekBot` / `ChatGLM-Spider` | 国内六家 AI 的检索源 |
| **训练型** | `GPTBot` / `ClaudeBot` / `CCBot` | 影响模型训练语料 |

**关键坑**：爬虫被拦 = **在 AI 答案里彻底不可见，且没有任何报错提示**。
既有的 `Disallow: *` 式写法或不完整的 UA 列表会让 AI 静默地看不见你。

本次改为**显式逐条 Allow** 17 个 UA，并声明 `LLMs-Txt: https://xiaominart.com/llms.txt`。
训练型也一并放行（注明：日后若想收紧，只需把训练型改 Disallow，不影响引用型）。

#### ③ `src/layouts/Layout.astro` —— JSON-LD 升级为实体图谱

由单节点改为 **4 节点 `@graph`**，用 `@id` 把品牌名/英文名/域名**合并成一个实体**：

```js
{'@context': 'https://schema.org', '@graph': [
  { '@type': 'Organization', '@id': '/#organization',
    name: '小民艺术',
    alternateName: ['XIAOMINART', 'Xiaomin Art', '小民艺术 XIAOMINART'],
    knowsAbout: [...10 项...], makesOffer: [...4 项 Service...] },
  { '@type': 'ProfessionalService', '@id': '/#service',
    parentOrganization: { '@id': '/#organization' }, priceRange: '咨询制' },
  { '@type': 'WebSite', '@id': '/#website',
    publisher: { '@id': '/#organization' } },   // ← 实体互链
  { '@type': 'ItemList', itemListElement: [...5 个 SiteNavigationElement...] }
]}
```

**为什么要 `@id` 互链**：AI 需要知道「小民艺术」「XIAOMINART」「xiaominart.com」
**是同一个东西**。没有互链时，它们可能被当成三个独立实体，品牌权重被稀释。
`knowsAbout` 是告诉 AI「这个实体在哪些话题上是相关的」——正是 AI 决定要不要引用你的依据。

### 1.2 GEO 内容补充（`bcb6489`）

**发现并修复一个真实的信息缺陷**：

`pricing-guide` 页面原先只列「定制作品」起步价（¥3,000 / ¥8,000 / ¥30,000 / ¥50,000），
**与用户实际问的送礼场景脱节**。当用户在 AI 里问「手写书法礼品多少钱」，
AI 抓到这个页面只会摘出「¥8,000 起」，与实际 ¥100–300 的入门送礼价**差 80 倍**，
既误导用户又损失转化。

**修复**：改为**现货线 / 定制线两条并列**，数据取自站内真实数据源：

```js
const retailPrices = readyMadeWorks.map((w) => w.price);
const minRetail = Math.min(...retailPrices);   // 199
const maxRetail = Math.max(...retailPrices);   // 399
```

并补 5 条 FAQ（含 FAQPage 结构化数据），标题改为匹配用户实际问法：

```
价格参考｜手写书法礼品多少钱｜小民艺术 XIAOMINART
```

同步改动：

| 页面 | 改动 |
|---|---|
| `gift-guide` | FAQ 4 → 6 条；「多久发货」由「以…为准」改为**直接给天数**（7–10 / 10–14 / 14–21 个工作日） |
| `help` | FAQ 8 → 12 条；新增「送礼大概多少钱」「送长辈/老师/乔迁分别适合什么」「包装含什么」「定制流程多久」 |
| `llms.txt` | 新增「关键事实」段：价格三档、现货 199–399、定制起步价、发货时效、包装、售后口径 |
| `sitemap.xml.ts` | 纳入 `pricing-guide/` |

**写作原则**：先给事实再讲边界，不虚构承诺；每个数字都能在站内数据源核验。

## 附：本批次踩到的技术坑（供后续参考）

1. **git push 通道再次关闭**（`github.com`=000，`api.github.com`=200）
   → 改用 **GitHub Git Data API** 推送：POST blob → 建 tree → POST commit → PATCH ref
2. **沙箱禁止 Node spawn 子进程**：`execSync`/`execFileSync` 调 git/cmd 一律 `EBUSY`
   → 必须拆两步：bash/Python 侧导出 `.ghdata.json`，Node 侧只做纯 HTTP
3. **API 重建的 commit SHA 与本地不同**（本地 `d86a8ee` ↔ 远端 `f25bfe2`）
   → 下次推送**必须以远端真实 SHA 为 parent**，用 `git diff-tree` 取内容差异
4. **Node 的 `/tmp` = `C:\tmp`**，与 bash 的 `/tmp` 不是同一目录
5. **`undici` 必须在项目目录跑**（`node:undici` 不是内置模块）
